## 一、目标

让硬件表遍历器（`gfx_sprtab.v`）把 3200 个 8×8 精灵画出来。

**为什么做它**：BRAM 精灵缓存把引擎从 45ms 降到 0.92ms 后，**CPU 提交命令成了瓶颈**（每条命令 11 次 AXI-Lite 写 ≈ 7µs × 6400 命令 = 45ms）。表遍历器让 CPU 每精灵只写 2 个字，命令由硬件生成。

## 二、已修复（今天下午的成果，别重做）

### Bug：`gfx_regs` 表写寄存器未复位（**已修，关键**）

| 项 | 内容 |
|---|---|
| 症状 | `USE_SPR_TABLE=1` 固件上板后串口无输出、`shot` 无响应（`no SHOT header`）|
| 根因 | `tab_wptr`/`tab_waddr_r`/`tab_wdata_r`/`tab_byte`/`tab_acc` 等**没有复位值** → 上电为 x → BRAM 写地址 x → 表数据无效 → 遍历器生成 dst 随机命令 → `gfx_core` 卡死 |
| 修复 | `gfx_regs.v` 复位分支补齐 8 个寄存器（`tab_wptr<=0`、`tab_byte<=0`、`tab_acc<=0`、`tab_we_r<=0`、`sp_go_r<=0`、`tab_waddr_r<=0`、`tab_wdata_r<=0`、`reg_sp_fb/src/n`）|
| 验证 | 仿真 `tb_gfx_regs.v`：`TAB_WE waddr=0,1,2 wdata 正确`；上板：固件不再挂、`spprog=1400`、`cpu=1.87ms`、`tabspin=0` |

### 已证明正确的部分

1. **遍历器命令生成**：仿真 `tb_sprtab.v` 输出 `op=0 dst=0x08000000 w=8 h=8 ds=4096` / `op=1 src=0x08870000 ss=16` 正确
2. **遍历器+gfx_core 握手**：仿真 `tb_tab_core.v` → `ALL 6 COMMANDS DONE`
3. **端到端**：把遍历器 `rec` 硬编码成 `64'h0064_0064_0064_0064` → **上板 (100,100) 画出了精灵** ✅

**所以**：遍历器、MUX（`gfx_top` 的 `core_cmd_valid/data`）、`gfx_core` 全链路都通。**问题只在真实表数据**。

## 四、遗留问题与下一步

**症状**：`USE_SPR_TABLE=1` 时固件正常跑（spprog=1400、cpu=1.87ms）但**画面空**。

**已收集的证据**：
- `R_DBG`(0x88) 曾接 `tab_acc`（最后写入的表字）→ 读到 `0x00660A24` → **低16位=0x0A24=2596（old_x 超 1920 范围）**
- `g_old_x` 是 `int16_t`、px = `g_bx/BR_Q`（BR_Q=4）、`g_bx` 边界由 `brown_step` 限制在 0..(1920-16)*4 → **理论上 px 应 ≤1904**
- 硬编码表项能画 → **命令链路没问题**

**下一步建议（按顺序）**：
1. **读回表项**：给 `gfx_sprtab` 加 `output [31:0] dbg_tab0 = tab[0][31:0]`，接到 `gfx_regs.dbg_in`（`R_DBG=0x88`）。固件 SCAN 里已有 `rdw=` 读 0x88，直接看值。**注意**：上一次加这类探针时 RTL 改动被中断（未验证），先确认 map 通过。
2. **对比**：同帧打印 `g_old_x[bi][0]`（注意别在 SCAN 里直接打印未初始化变量，之前挂过一次）
3. **如果表里是 2596** → 查固件 `brown_step`/`g_old_x` 更新（可能 `FB_W`/`SPR_W` 宏或 `bi` 索引问题）
4. **如果表里是对的** → 查遍历器的 `rec` 解码（`rec[15:0]`=old_x、`rec[31:16]`=old_y、`rec[47:32]`=new_x、`rec[63:48]`=new_y）

## 六、注意事项（踩过的坑）

1. **改源码改 `work/gfx_demo/src/main.c`**，不是 `C:\fpga_work\sw\...`（后者会被 build 脚本覆盖）
2. **printf 里不要写 `\r\n` 通过 Python 补丁注入** —— 会被写成真实换行导致编译错误；要加调试优先用「全局变量 + SCAN 输出」
3. **`tab` 表项 64 位**（2 个 32 位字）：word0 = `old_x | old_y<<16`，word1 = `new_x | new_y<<16`；位图地址和擦除色是全局（`R_SPRSRC`=0xA0、`R_SPRFB`=0x9C、`R_SPRN`=0xA4）
4. **`R_SPRCTL`(0x7C) 写 1 启动**（上升沿）；`R_SPRDONE`(0x80) 读遍历器发出的命令数
5. **表 RAM 4096×64 位**（32KB）；128 位表项版本曾因 BRAM 64KB 导致 `Routing FAILED; congestion`
