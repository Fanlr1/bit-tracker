## 二、🚨 核心发现：AXI ID 截断冲突

### 证据链（全部来自源码）

```
Axi_Mux.v:417   parameter SLAVE_ID_WIDTH = 8
Axi_Mux.v:437   localparam MIW = MASTER_ID_WIDTH           ⇒ MIW = 8

ddr3_parameter.vh      `define AXI_ID_WIDTH  4
ddr3_top.v:103         input [AXI_ID_WIDTH-1:0] s_axi_awid ⇒ 4 位
system_top.v:182       wire [AXI_ID_WIDTH-1:0] s_axi_awid  ⇒ 4 位
```

**⇒ `Axi_Mux` 输出 8 位 ID 接到 4 位端口，Verilog 静默取低 4 位。**

### 原状与修复

| 主机 | 原值 | 原低 4 位 | **现值** | **现低 4 位** |
|---|---|---|---|---|
| BitBlt 读源 | `8'h10` | `0x0` | **`8'h18`** | **`0x8`** |
| BitBlt 读目标 | `8'h12` | `0x2` | **`8'h1A`** | **`0xA`** |
| BitBlt 写 | `8'h14` | `0x4` | **`8'h1C`** | **`0xC`** |
| 视频读 | `8'h20` | ~~`0x0`~~ 🚨 | **`8'h1E`** | **`0xE`** |

**原先「视频读」与「BitBlt 读源」共用低 4 位 `0x0`。**

### 为什么这是真问题

**AXI ID 的作用是让 Master 区分【并发事务】的响应。**
`Axi_Mux` 内部有 `Wr_Ctrl` / `Rd_Ctrl` / `Addr_Ctrl` / `Info_Fifo` —— **这些正是为多通道并发而存在的**。

**⇒ 两个主机同 ID ⇒ DDR3 返回的响应无法区分 ⇒ 读数据可能串台。**

### ⚠️ 为什么所有测试都没抓到

| 测试 | 为什么漏 |
|---|---|
| **M1 单元** | 只测单模块，没有多主机 |
| **端到端** | 只有 BitBlt 三引擎（ID 本就错开），**视频通路不在那个 TB 里** |
| **整机综合** | 不检查 AXI 语义 |
| **仿真** | **AXI 协议允许 ID 重复，不报错** |

**⇒ 只有交叉核对位宽才能发现。这是本次审计唯一的、也是最重要的产出。**

### 验证修复生效

**综合报告的分层信息里直接带了参数值**：

```
+u_video_out:bitblt_video_out(AXI_ID=8'b011110)
                                    ^^^^^^^^^^
                                    0b011110 = 0x1E, low4 = 0xE  ✓
```

**⇒ 不必另写 TB，从综合报告即可确认。**
（同理，之前确认 `Axi_Mux` 的 `X5` 生效，也是靠报告里的 `AXI_CHANNEL_NUM=5`。）

## 三、❌ 被推翻的方案：`ID_MODE_SEL = "Extend"`

**我一度建议启用 `Extend` 模式**（M 侧 ID = S 侧 ID + 通道号），理由是「各通道 ID 天然不冲突」。

**读实现后发现是错的**（`Axi_Mux.v:1330-1338`）：

```verilog
// Normal 模式
assign M_AW_Id =                S_AW_Id[AW_Cnl_Num]  ;   // 8 位

// Extend 模式
assign M_AW_Id = {AW_Cnl_Num , S_AW_Id[AW_Cnl_Num] };    // 3+8 = 11 位
```

**⇒ 通道号拼在【高位】。截断到 4 位（保留低位）后，通道号全部丢失，
各通道 ID 仍等于各自的 `S_ID` 低 4 位 —— 与 `Normal` 模式【完全一样】。**

**⚠️ 好在先读了实现再动手。** 这再次印证本项目的教训：
**参考文档与直觉只能指方向，结论必须从实际代码或输出里读。**

## 四、⚠️ 仍未解决：SoC 用哪个 ID

```
soc.v   output [7:0] io_ddrA_aw_payload_id;
        output [7:0] io_ddrA_ar_payload_id;
```

**SoC 的 ID 也是 8 位，同样被截断到低 4 位，而 `soc.v` 加密，看不到内部。**

**⇒ 现有做法是「概率规避」**：把四个 ID 放在 `8/A/C/E`，**把 `0`–`7` 让给 SoC**
（一个 AXI Master 同时开 8 个并发事务已属罕见）。

**⚠️ 这是规避，不是证明。** 三条确认途径：

| 途径 | 可行性 |
|---|---|
| **板上实测** | 最直接，需板子 |
| **仿真 `system_top`** | 需 Questa license + 能解密 `soc.v` |
| **查 Efinix 文档** | 未必有此细节 |

**⇒ 建议板上加一项检查：连续跑 BitBlt 拷贝并反复校验数据一致性。若 ID 撞车，会出现间歇性数据错误。**

## 五、其余五个维度的审计结果

| # | 维度 | 结论 | 依据 |
|---|---|---|---|
| **1** | **地址一致性** | ✅ | 四处区间不重叠；驱动与 RTL 的值逐位对上 |
| **2** | **像素格式** | ✅ | `0xFFRRGGBB` → `RR/GG/BB` 链路吻合 |
| **4** | **中断链路** | ✅ 接通，⚠️ 一项存疑 | PLIC 30 四环对齐；**脉冲宽度存疑** |
| **5** | **位宽** | ✅ | 全部地址 < `0x0FFFFFFF`，截断不回绕 |
| **6** | **内存布局** | ✅ | 见下 |

### 地址区间（逐项算过）

```
程序 : 0x00001000 .. 0x0001FFFF   (124 KB, 链接脚本 ram 区间)
FB A : 0x08000000 .. 0x0812BFFF   (1228800 B)
FB B : 0x0812C000 .. 0x08257FFF   (1228800 B)
SPR  : 0x09000000 .. 0x09003FFF   (16384 B)
```

### 中断链路（逐环确认）

```
bitblt_top.axi_interrupt
  ↓  system_top:994  .axi_interrupt (blt_interrupt)
  ↓  system_top:362  wire blt_interrupt;
  ↓  system_top:672  .axiAInterrupt (blt_interrupt)
soc.v  system_axiA_interrupt_plic_gateway_ip <= axiAInterrupt;
  ↓
soc.h  #define SYSTEM_PLIC_SYSTEM_AXI_A_INTERRUPT 30
  ↓
驱动   plic_set_enable(..., SYSTEM_PLIC_SYSTEM_AXI_A_INTERRUPT, 1)
```

**✅ 排除了「中断风暴」**：`bitblt_addr_gen.v:41` 明确写着 `// one-cycle pulse`，
且每周期默认 `done <= 1'b0` ⇒ **不会出现 ISR 结束立刻重入的死循环**。

**⚠️ 但暴露出相反风险**：`done` 仅 10 ns 宽，而
`soc.v` 里 `system_axiA_interrupt_plic_gateway_waitCompletion` 这个名字
**提示 gateway 可能要求中断线保持到被应答**。若是，脉冲会丢失。

**⇒ 缓解已内置**：驱动等待是**有界**的 —— 收不到中断会打印
`WARNING: no done interrupt` 后继续，**不会卡死**。

## 六、审计脚本（本次的可复用产出）

**位置**：`C:\fpga_work\scripts\audit-bitblt.ps1`

**用法**：

```powershell
powershell -ExecutionPolicy Bypass -File C:\fpga_work\scripts\audit-bitblt.ps1
# exit 0 = 全部通过，exit 1 = 有失败
```

### 五类检查，每类对应真实事故

| # | 检查 | 对应历史 |
|---|---|---|
| **1** | **AXI ID 低 4 位唯一，且都在 `8..F`** | **本次审计发现** |
| **2** | **内存区间不重叠 + 都在 28 位内** | 预防 |
| **3** | **驱动/RTL 常量一致**（`fb_base` / `stride`）| 预防 |
| **4** | **关键模块在网表里**（5 个）| **两次「假 PASS」** |

### 运行结果（当前状态）

```
=== 1. AXI ID ===      found 4 master IDs: 0x18, 0x1A, 0x1C, 0x1E      2/2 PASS
=== 2. memory ===      不重叠 + 28 位内                                  5/5 PASS
=== 3. constants ===   驱动与 RTL 一致                                   4/4 PASS
=== 4. netlist ===     5 个模块都在                                      5/5 PASS
=== 5. widths ===      AXI_ID_WIDTH=4 等                                 3/3 PASS

AUDIT: all checks passed        exit code: 0
```

### ⚠️ 写脚本时踩的两个坑（都值得记）

**① PowerShell 字符串定界**
正则里含 Verilog 的 `8'h`，那个 `'` 在**双引号字符串**中与定界规则冲突，
**解析器报错却指向完全无关的第 33 行**。
**⇒ 改用单引号字符串，`'` 写成 `''`。**

**② 读错了文件**
`r_fb_base` 在 `bitblt_axi_slave.v` 里，脚本却从 `system_top.v` 找。

**⚠️ 但坑 ② 暴露的方式是好的**：脚本报 `could not parse` 而**不是静默通过**。
**这是给 `Check` 加「找不到也必须显式判定」的价值** ——
**一个读错路径的检查若默认"通过"，就变成了永久的假保证。**
