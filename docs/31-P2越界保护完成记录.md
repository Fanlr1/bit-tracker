## 一、P2 的实际内容（与原计划不同）

**原计划写的是「硬件裁剪」**，但动手前发现那个设计有个前提问题：

**裁剪需要知道 sprite 在屏幕上的坐标（`dst_x`/`dst_y`），而寄存器里只有 `DST_ADDR`（绝对地址）。**

| 方案 | 代价 |
|---|---|
| 加 `DST_X`/`DST_Y` 寄存器，硬件算地址 | 改动大，且要重写驱动接口 |
| 从 `DST_ADDR` 反算坐标 | 需要除法，代价高 |
| **CPU 算好裁剪参数再下发** | **CPU 只是 O(1) 比较，本来就便宜** |

**⇒ 而真正【必须由硬件保证】的是另一件事**：

```
部分越界 ⇒ 写到 framebuffer 之外的 DDR ⇒ 【破坏别人的数据】
```

**⇒ 这不是性能问题，是内存安全问题。** **⇒ P2 拆成两半：**

| 半 | 谁做 | 内容 | 状态 |
|---|---|---|---|
| **① 越界保护** | **RTL** | **矩形越出 framebuffer 时拒绝/截断** | ✅ **本次完成** |
| **② 实际裁剪** | **驱动** | **CPU 算交集，下发裁剪后的偏移与尺寸** | ⬜ 待做 |

## 二、实现

### 2.1 `bitblt_addr_gen` 新增两个端口

```verilog
input  wire [AW-1:0] fb_start,
input  wire [AW-1:0] fb_end,      // one past the last valid byte
output reg           oob,         // sticky until the next start
```

**⇒ 边界来自 `FB_BASE` / `FB_SIZE_H` / `FB_CFG`，所以双缓冲切换时【自动跟随】。**

### 2.2 两层保护

| 层 | 时机 | 行为 |
|---|---|---|
| **① 起始越界** | **`S_IDLE`** | **立即 `done` + `oob = 1`，一行都不搬** |
| **② 逐行越界** | **`S_LINE` 收到 ack 后** | **有效行照搬，越界行【提前结束】** |

**⇒ 关键设计**：**越界时【仍然产生 `done`】** —— **否则 CPU 会死等一个永远不来的完成信号。**

### 2.3 `STATUS[2]` 现在报告两种错误

```verilog
assign engine_status = {29'd0, (wr_b_error | addr_oob), addr_done, addr_busy};
```

**⇒ 写响应错误** 或 **越界** —— **都是「引擎没做你要它做的事」。**

### 2.4 横向越界由驱动负责

**⇒ 一行是一次突发，拆开就损失了赛题要求的突发效率。** **⇒ 横向留给 CPU 裁剪。**

## 三、验证

### 3.1 新增 4 个用例

```
PASS oob/below:   refused, done asserted, oob=1, 0 lines
PASS oob/above:   refused, done asserted, oob=1, 0 lines
PASS oob/overrun: 2 valid rows transferred, then stopped with oob=1
PASS oob/clears:  next valid transfer reports oob=0
```

**⇒ `oob/overrun` 是关键的**：**前两行地址有效【照搬】，第三行越界【停止】。**

### 3.2 反向注入

**注入 A：`line_fits` 永远返回真**
```
RESULT: FAILED with 8 error(s)
FAIL oob/below / oob/above
FAIL line 0 dst: got 00007000 want 00008f80      ← 越界地址【真的被搬了】
```
**⇒ 正是这个功能要防的事。**

**注入 B：`oob` 永远为 0**
```
RESULT: FAILED with 2 error(s)
FAIL oob/below: done=1 oob=0 lines=0 (want 1/1/0)   ← 只错在标志
```
**⇒ 两个注入揭示不同的失效模式。**

### 3.3 完整回归与比特流

```
PASS=12  FAIL=0   （零警告）
map / interface / pnr / pgm : PASS
bitblt_system.bit : 2007.5 KB

EFX_LUT4  : 11874    （上版 11898）
EFX_FF    : 10603    （上版 10580）
EFX_DSP48 : 31       （上版 30）
EFX_RAM10 : 70
```

**时序**：`core_clk` 3.021 → **2.603**（新增比较器所致，余量仍 26%）；其余全部收敛。

## 四、⚠️ 途中发现并修复的一个真实缺陷：`function automatic`

**第一版把边界判断写成了函数**：

```verilog
function automatic line_fits;
    input [AW-1:0] a;
    reg   [AW:0]   a_plus;      ← automatic 函数的局部变量
    ...
endfunction
wire first_line_ok = line_fits(dst_base);
```

**结果**：

| 测试 | 结果 |
|---|---|
| **单元 TB**（`fb_start`/`fb_end` 是**常量**） | ✅ **PASS** |
| **端到端 TB**（它们是**会变的寄存器值**） | ❌ **9 个 FAIL** |

**⇒ 现象**：`oob = 0`、地址也在窗口内，**但 `addr_gen` 完全不启动**。

**⇒ 诊断过程**：
1. 观测 `dst_addr` / `fb_start` / `fb_end` ⇒ **全部正确**
2. 观测 `addr_oob` ⇒ **0**（说明是复位初值，`start` 根本没处理）
3. **二分法**：把喂给 `addr_gen` 的边界短路成「永远通过」⇒ **`PASS: all checks OK`**
4. **⇒ 定位到边界判断逻辑本身**

**⇒ 修复**：**改成内联的 `wire` 表达式，彻底不用函数。**

```verilog
wire [AW:0] first_line_end = {1'b0, dst_base} + {1'b0, bytes_this_line};
wire        first_line_ok  = (dst_base >= fb_start) &&
                             (first_line_end <= {1'b0, fb_end});
```

**⚠️ 教训**：**`automatic` 是 SystemVerilog 特性，在 `-g2005` 下的行为不可依赖。** **而且「常量测试通过、变量测试失败」这个形态极难从单测发现。**

## 五、⚠️ 一次严重失误：文件被截断

### 5.1 发生了什么

**清理调试代码时，我用正则批量删除 `$display("  DBG ...")` 行**：

```powershell
$t = [regex]::Replace($t, '(?m)^\s*\$display\("  DBG [^\r\n]*\r?\n(\s+[^\r\n]*\r?\n)*', '')
```

**⇒ 结果：`tb_bitblt_top.v` 从 782 行变成 565 行 —— 丢了 217 行。**

### 5.2 根因

**第二个正则里用了 `\s+`**：

```powershell
'(?m)^\s*repeat \(4\) @\(posedge clk\);\r?\n\s*\$display\("  DBG post-start[^\r\n]*\r?\n\s+[^\r\n]*\r?\n'
                                                                                    ^^^
```

**⇒ `\s` 包含换行符** ⇒ **`\s+` 一路吃掉了后面所有行**，直到文件末尾。

### 5.3 恢复过程

| 版本 | 行数 | 有声明 | 有主体 |
|---|---|---|---|
| **被截断的** | **565** | ✅ | ❌ |
| **旧版（`fpga_work\tb\`）** | **611** | ❌ | ✅ |

**⇒ 两者互补** ⇒ **以 611 行为基底，用 `edit` 工具（精确字符串匹配，不用正则）补 4 处**：

1. **6 个声明**（`blend_src_ref` 等）
2. **`FB_BASE` 归零段**
3. **混合测试段 + SLVERR 注入段**
4. **模型里的 `inject_bresp_err` 声明 + `S_RESP` 的 `bresp` 赋值**

**⇒ 恢复后 768 行，21 项检查全部 PASS。**

### 5.4 ⚠️ 这是第四次批量替换出错

| # | 错误 | 后果 |
|---|---|---|
| **1** | **`0x1234_5678u`**（Verilog 的分隔符写进 C） | **编译错误，当场发现** |
| **2** | **`edit` 误删 `input bytes;`** | **当场复核发现** |
| **3** | **正则删掉 `blend_bg_ref` 等 6 个声明** | **编译错误，当场发现** |
| **4** | **正则 `\s+` 吃掉 217 行** | **⚠️ 破坏性，需要恢复** |

**⇒ 共同根因**：**都在用「模式匹配」改代码，而模式匹配的边界判断很容易写错。**

**⇒ 而 `edit` 工具的精确字符串匹配【从未出错】** —— **第 2 次虽然写错了内容，但那是我的错，不是工具的错。**

### 5.5 今后的规则

**⇒ 定死两条**：

| # | 规则 |
|---|---|
| **1** | **改代码一律用 `edit` 工具（精确匹配），不用正则、不用 `-replace`** |
| **2** | **批量改动前先 `Copy-Item` 备份**（这次的备份是【事后】才做的，纯属侥幸有两个版本可对比） |
