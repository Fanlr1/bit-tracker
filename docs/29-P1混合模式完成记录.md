# P1 完成记录：三种额外混合模式

> 日期：2026-10-06
> 对应 `28-待办优先级.md` 的 **P1**
> 状态：**RTL + TB 完成并验证；驱动演示待做**

---

## 一、做了什么

在原有 4 种操作之外，新增 3 种混合模式：

| 模式 | 公式 | 效果 |
|---|---|---|
| **MODE_ADD** | `min(fg + bg, 255)` | **加法混合 / 发光** |
| **MODE_MUL** | `fg × bg / 255` | **乘法混合 / 阴影** |
| **MODE_SCREEN** | `255 − (255−fg)(255−bg)/255` | **滤色 / 提亮** |

**⇒ 原 4 种**：COPY · FILL · ALPHA · KEY（赛题要求的）

---

## 二、为什么成本极低

**关键洞察**：**四种混合需要的都是「除以 255」，而三种新分子的取值范围【恰好都在 [0, 65025]】—— 和 ALPHA 的分子完全一样。**

```
alpha  : fg*a + bg*(255-a)  <= 65025
mul    : fg * bg            <= 65025
screen : (255-fg)*(255-bg)  <= 65025
```

**⇒ 已有的精确除法恒等式 `q = (x + 1 + (x>>8)) >> 8` 可以【原样复用】，只换输入。**

**⇒ 实现上**：**先把分子选出来，再送进【同一个】除法器** —— **不是三个除法器并行再选。**

**⚠️ 这个设计被注入测试验证过**：把共享的除法器改坏，**ALPHA 和三种新混合【同时】失败**（10 个错误）—— **证明它们确实共用一份硬件。**

## 四、验证

### 4.1 新增的 12 个用例

```
ADD  : saturates-B / black+black / saturates-all / exact-255
MUL  : midpoint / white*white / black*white / mixed
SCREEN: midpoint / black+black / white+black
      + mul/write-enable-high（混合模式必须仍然写使能）
```

**期望值【全部手算】**，不是从 DUT 抄的。

### 4.2 ⚠️ 手算过程中发现了一个自己的错误

```
FAIL mul/mixed: got px=ff800001 want ff800000
```

**我的用例**：`fg = 0xFFFF0001`，`bg = 0xFF8000FF`

```
B 通道：fg_b = 0x01 = 1，bg_b = 0xFF = 255
x = 1 × 255 = 255  ⇒  q = (255+1)>>8 = 1
```

**⇒ 实现是对的（1），我在注释里写成「1×1=1 → 0」是错的** —— **把 `bg` 的 B 通道看成了 `0x01`。**

**⚠️ 而这恰好证明【这条测试真的能失败】** —— **它抓到了我手算的错误。如果期望值是从 DUT 抄来的，这个错会跟着一起"通过"，正是 `docs/20` 批评的形态。**

### 4.3 反向注入

**注入 A：把共享的 `/255` 改成 `>>8`**
```
RESULT: FAILED with 10 error(s)
FAIL alpha/a=255 / alpha/a=0 / alpha/midpoint / alpha/pixel-A ...
```
**⇒ 4 个 ALPHA 用例 + 6 个新用例同时失败** ⇒ **证明除法器确实共享。**

**注入 B：ADD 去掉饱和**
```
RESULT: FAILED with 2 error(s)
FAIL add/saturates-B:  got ff70d050 want ff70d0ff
FAIL add/saturates-all: got fffefefe want ffffffff
```
**⇒ 只有涉及饱和的 2 个用例失败，`add/black+black` 仍 PASS** ⇒ **用例之间有区分度。**

## 六、为什么这个"赛题没要求"的功能值得做

**⇒ 判据来自 `27-创新点评估.md`**：**是否服务于赛题立意。**

| 判据 | 评估 |
|---|---|
| **① 让 CPU 更"高层"？** | ★ **CPU 不用自己做混合运算** |
| **② 让混合更强？** | **★★★ 直接扩展"混合"能力** |
| **③ 可演示可量化？** | **★★★ 发光弹幕一眼看出** |

**⇒ 中三条，而且成本极低。**

**⇒ 实际价值**：**赛题高阶 3 的弹幕场景里，发光（ADD）和阴影（MUL）是让画面"像游戏"的关键** —— **只有 Alpha 和 Keying 做不出这两种效果。**
