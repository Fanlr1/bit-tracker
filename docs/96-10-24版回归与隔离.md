# 96 - 10-24 版 rtl 存在 copy-readback 回归（已隔离）

> 接 [docs/95](95-LOCATOR停用与判据修正.md)。本文记录一次**失败的修复尝试**及其隔离。

## 一、事实

| 版本 | md5 | copy-readback | 结论 |
|---|---|---|---|
| **01:00 版**（`bitblt_system-8192-rwatchdog-20261017.bit`）| `39b89162…` | **0 错** | ✅ 可用 |
| **10-24 realign 版**（`bitblt_system-realign-20261024.bit`）| `6d513fb4…` | **959,128 错** | ❌ 已隔离 |
| 10-24 + `o_blanking` 恢复 | （新构建）| **959,128 错** | ❌ 同上 |

**关键**：两次测量都是 **959,128**，一个像素不差。

## 二、被排除的原因

**`o_blanking` 不是原因。** 原假设是：`o_blanking = ~de_raw` 让软件在水平消隐期间就翻页，导致撕裂与 95 万像素错误。

实测：把它恢复成正确的 `~v_active`、重新构建、重新烧写后，**错误数完全不变**（仍 959,128）。

⇒ 该假设**被证伪**。`o_blanking` 的正确性另有价值（翻页时机），但它不解释这个回归。

## 三、最可能的来源

10-24 的 rtl 相对 01:00 版多出的改动包括：

1. **`rd_row` / `px_in_line` 每帧垂直消隐归零**（本意修白条漂移）；
2. **10-17 全天的慢态修复尝试**：`line_start` 每 16 拍重发、`src_started` / `dst_started` latch —— 这些**从未在板上确证**（见 [docs/92](92-慢态尝试与未确证.md)）；
3. 若干观测端口。

`copy-readback` 测的是"拷 64×64 再读回"，与扫描输出无关，所以 (1) 不太可能直接造成它；**(2) 那两处 `src_start`/`dst_start` 的启动条件改动更可疑**——它改变了 DMA 的启动时机，可能让读侧在写侧未就绪时启动。

## 四、处置

- **01:00 版已恢复**为 `C:/fpga_work/sys/outflow/bitblt_system.bit`（md5 `39b89162…`）；
- **10-24 版已隔离**：`work/bitstreams/QUARANTINE-regress-copyreadback.bit`；
- 源码侧的改动**保留**（它们可能是对的，只是与别处组合后出问题），但**不用于出比特流**，直到能把回归定位到具体一处。

## 五、下次如何分离

按以下顺序逐步加回，每步一次板上 `copy-readback`：

1. 01:00 版基线（已知 0 错）；
2. + `rd_row` 归零 —— 单独验证；
3. + `line_start` 重发 —— 单独验证；
4. + `src_started` / `dst_started` latch —— 单独验证。

**哪一步把 `mismatching pixels` 从 0 变成 959,128，问题就在那一步。**

## 六、教训

**"修复"必须一次只加一处，并立刻用 `copy-readback` 验伤。** 本轮一次加了四处改动（归零 + 两处启动条件 + 观测端口），
结果失败后只能靠排除法，而第一轮排除（`o_blanking`）就用了整整一次构建（171 秒）+ 一次上板。
