# 118 · DVI 不稳定的根因与修复（900 精灵达成 @ 59.2 fps）

> 日期：2026-11-01 12:40
> 结果：**900 × 16×16 精灵 @ 59.2 fps，DVI 稳定**
> 备份：`work/backup/golden900-20261101/`（bit md5 `83b8c75de3e324a74ec8424e429225c0`）

## 一、根因

**`dvi_encoder.v` 的输出是组合逻辑直连 IO 引脚**：

```verilog
assign tmds_data0 = blue;   // encode 的输出寄存器 -> 直接到 IO
assign tmds_data1 = green;
assign tmds_data2 = red;
```

- `encode.v` 内部已经有 `output reg [9:0] dout`（打拍），但从该寄存器到 IO 引脚之间**只有一层 assign**
- 布局紧凑时（黄金版 700 精灵）这段路径短 → 稳定
- 布局分散时（900 精灵版，LUT 利用率 83.8%）这段路径被拉开 → **IO 时序裕量不足 → DVI 闪烁/黑屏**
- 时序报告佐证：`pix_clk -> pix_clk_fast` 路径终点 `tmds_data1_o[4]`，slack **-3.702 ns**

## 二、修复

在 `dvi_encoder.v` 加**输出管道寄存器**（pix_clk 域）：

```verilog
reg [9:0] red_q, green_q, blue_q;
always @(posedge pixelclk) begin
    red_q   <= red;
    green_q <= green;
    blue_q  <= blue;
end
assign tmds_data0 = blue_q;
assign tmds_data1 = green_q;
assign tmds_data2 = red_q;
assign tmds_clk   = 10'b1111100000;
```

**效果**：IO 引脚前的最后一段变成「寄存器 → IO」，PnR 会把输出寄存器放在引脚附近 → 时序裕量与布局无关 → **任何 PnR 结果都稳定**。

## 七、补充（12:50 实测）：输入端打拍是黑屏元凶

**症状**：900 精灵版 DVI 会「十几~二十秒黑一次，1~2 秒后恢复」。

**对照实验**：

| 配置 | 欠载/帧 | rows/fr（开机自检）| 黑屏 |
|---|---|---|---|
| 黄金版 700（无任何打拍）| 0.0 | 0.0 | 无 |
| 900 + 输入打拍 + 输出打拍 | 1.94 | 1.1~2.0 | 十几秒一次 |
| 700 + 输入打拍 + 输出打拍 | 1.89 | 1.1 | 二十秒一次 |
| **900 + 仅输出打拍（移除输入打拍）** | **0.94** | **0.6** | **两分钟一次** |

**结论**：
- 黑屏与精灵数量无关（700 和 900 都黑）
- **输入端打拍（`vid_rgb_q/vid_de_q/vid_hs_q/vid_vs_q`）是主要元凶** —— 它改变了 data→encode 的相位关系
- 移除后欠载从 1.89 降到 0.94，黑屏从二十秒一次降到两分钟一次
- 残留偶发（~2 分钟一次）疑似 DVI 偶发失锁（显示器重新同步需要 1~2 秒）
