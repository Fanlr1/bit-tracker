# tb_mux_video 根因：队列数组越界

> 日期：2026-10-06
> 状态：✅ **已修复，`RESULT: PASS`（pixel errors = 0）**
> 关联：`docs/36`（FIFO 组合环路，前一阶段）

---

## 一、结论

**⇒ 一个 4 vs 8 的数组大小错，串起了 `tb_mux_video` 的全部症状。**

```verilog
// tb_mux_video.v（修复前）
localparam QD = 4;
reg [31:0] q_addr [0:QD-1];      // ← 只有 4 个位置（索引 0..3）
reg [7:0]  q_id   [0:QD-1];
reg [7:0]  q_len  [0:QD-1];
reg [2:0]  q_wr   = 3'd0;        // ← 3 位指针，走到 8 才回绕
```

**⇒ 第 5 个 AR 到达时 `q_wr = 4`，写的是 `q_len[4]` —— 越界。**

---

## 二、症状链：一个 `x` 如何串起全部现象

```
q_len[4] 越界写 ⇒ 写入被丢弃，读回 x
    ↓
cur_len = x
    ↓
m_rlast = (beat_idx == cur_len) = x
    ↓
if (m_rlast) 中的 x 在 Verilog 里【按假处理】
    ↓
burst 的结束条件【静默失效】
    ↓
beat_idx 一路涨到 5644（应停在 159）
bursting 永不归零，m_rvalid 挂了 108170 拍
    ↓
DUT 每 5 拍接收一个 beat ⇒ 握手 6128 次
    ↓
每个 beat 拆 4 个像素 ⇒ 写 24495 个
    ↓
FIFO 灌满 ⇒ splitting 卡在等空间
    ↓
need_line 被 !splitting 挡住 ⇒ 只发了 4 次读（应 37 次）
    ↓
35 行里 20528 个像素是重复的旧数据
```

### 修复前后的数字对比

| 指标 | 修复前 | 修复后 |
|---|---|---|
| **pixel errors** | **20528** | **0** |
| **AR bursts S4** | **4** | **37** |
| **v_rvalid 高电平拍数** | **108166** | **28834** |
| **m_rvalid 高电平拍数** | **108170** | **28838** |
| **AXI beats accepted** | **6124** | **5796** |
| **RESULT** | FAIL | **PASS** |

**⇒ 修复后 `28834 / 5796 ≈ 5`** —— **每 5 拍一个 beat，正是 `splitting` 拆 4 像素的节奏。数字自洽了。**

---

## 三、修复

```verilog
// 数组大小必须匹配【指针的回绕点】，而不是 QD
localparam QD      = 4;
localparam QSLOTS  = 8;              // = 2**3，3 位指针的回绕点
reg [31:0] q_addr [0:QSLOTS-1];
reg [7:0]  q_id   [0:QSLOTS-1];
reg [7:0]  q_len  [0:QSLOTS-1];
```

**⇒ 同时把队列非空判据从 `q_cnt > 0` 改成 `q_wr != q_rd`**（指针不等，不依赖计数器）。

**⚠️ 注意**：**判据这一改动【本身没有解决问题】** —— 因为根因在数组越界。**但它让判据不再依赖一个可能出错的计数器，是独立的加固。**

## 四、⚠️ 为什么我查了这么多轮才找到

| 我的判断 | 结果 |
|---|---|
| 「`Axi_Mux` 把 beat 放大 7.6 倍」 | ❌ **错** —— 两侧信号本就是同一个（`S_R_Valid = R_Act_Cnl_List & M_R_Valid`）|
| 「TB 的从设备模型完全正确」 | ⚠️ **半对** —— 逻辑对，但【数组越界】是它的问题 |
| 「`q_cnt` 虚高导致越界启动」 | ❌ **错，且改完毫无效果** |
| 「初始化数组就能挡住」 | ❌ **无效** —— **初始化循环也用了 `QD` 作上界，同样没覆盖索引 4** |

### 关键教训

| # | 教训 |
|---|---|
| **1** | **未初始化的 `x` 会【静默禁用控制路径】** —— `if (x)` 在 Verilog 里按假处理，不报错、不警告。**这类 bug 只能靠逐拍波形抓** |
| **2** | **数组大小要和【指针回绕点】对齐，不是和【深度】对齐** —— 深度 4 但指针 3 位 ⇒ 能寻址 8 个位置 |
| **3** | **「改了没效果」是重要信号** —— 它直接排除了那个假设。**我改 `q_cnt` 判据后数字一模一样，那时就该转向，而不是再改初始化** |
| **4** | **两侧信号可能是同一个** —— `v_rvalid` 和 `m_rvalid` 之间只隔一层与门，**我把它们当成独立的观察点，得出了「放大 7.6 倍」的错误结论** |

## 五、副产物：探针本身就是性能杀手

**⇒ 逐拍打印（`$display` + `$fflush`）让 `tb_mux_video` 从 3 秒变成 200 秒。**

| 配置 | 耗时 |
|---|---|
| **带 400 行逐拍探针** | **约 200 秒** |
| **清理后** | **3 秒** |

**⇒ 所以「仿真慢」在排查期间【不一定是设计问题】** —— **先数一数自己打了多少行。**

**⇒ 而 3 秒意味着 `tb_mux_video` 可以进回归套件。**
