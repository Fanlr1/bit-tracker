## 三、RISC-V 程序怎么进去

**⚠️ 这是本项目【最大的未知之一】。**

```
复位向量 = 0xF9000000（片内 RAM，跑 SPI-Flash bootloader）
```

**⇒ 所以正常路径是【程序烧进 SPI Flash】**，**而 Flash 的烧写方式【尚未确认】**。

| 方案 | 说明 | 状态 |

## 四、首次上电的推荐顺序

**⇒ 目标：每一步只引入一个新变量。**

```
① 只烧比特流，不烧程序
   ⇒ 看 HDMI 有没有输出
   ⇒ 预期：【能看到画面】，因为寄存器复位值就打开了扫描输出
     （FB_BASE=0x08000000 · 640×480 · stride 2560 · enable=1）
   ⇒ ⚠️ 但 framebuffer 从未被写过 ⇒ 画面内容是【DDR3 上电后的随机值】
   ⇒ 所以看到"雪花"是【正常的】，看到"全黑"也是正常的
   ⇒ ❗ 只有【完全没有信号 / 显示器不识别】才是问题

② 烧一个【最小程序】：只打印一行然后死循环
   ⇒ 验证：CPU 能跑、UART 能输出
   ⇒ 这一步验证了【工具链 → 板子】的完整路径

③ 烧完整 demo
   ⇒ 跑 board-check.ps1 抓日志
   ⇒ 按 21 号清单逐项验证

④ 确认上屏链路
   ⇒ 用纯色填充，看屏幕是否变色
   ⇒ 这是【渲染结果能上屏】的第一个确证
```

**⚠️ 第 ① 步特别重要**：**如果比特流本身有问题（引脚错、PLL 不锁），后面全都是白费力气。**

## 五、`board-check.ps1` 的用法

```powershell
cd C:\fpga_work\scripts

# 看板子枚举成哪个串口
.\board-check.ps1 -List

# 抓日志并判定
.\board-check.ps1 -Port COM3

# 离线重跑判定（已有日志）
.\board-check.ps1 -FromFile board_log.txt
```

**⇒ 它有 6 条规则**，其中**主判定读固件自己发的 `[TEST:PASS/FAIL]`**，**辅判定用自然语言兜底**（覆盖「固件来不及发标记就挂掉」的情况）。

**⚠️ 但它【看不到屏幕】** —— **颜色、撕裂、错行、画面冻结仍要人眼确认。**
