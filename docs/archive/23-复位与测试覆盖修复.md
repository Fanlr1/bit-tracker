## 二、复位类

### 2.1 `axi_slave`：26 个寄存器无复位

**报告**：
```
axi_slave.v:209/236/268/301/313   15 个捕获寄存器【完全无复位】（同模块另有异步复位块）
                                  ⇒ 上电后仿真 X、FPGA 0 ⇒ 综合/仿真不一致的经典来源
```

**实际清点后是 26 个寄存器、5 个块**：

| 块 | 寄存器 |
|---|---|
| AW 捕获 | `awidReg` `awaddrReg` `awlenReg` `awsizeReg` `awburstReg` `awlockReg` `awcacheReg` `awprotReg` `awqosReg` `awregionReg` |
| B 响应 | `bidReg` `brespReg` `bvalidReg` |
| AR 捕获 | `aridReg` `araddrReg` `arlenReg` `arsizeReg` `arburstReg` `arlockReg` `arcacheReg` `arprotReg` `arqosReg` `arregionReg` |
| R 响应 | `ridReg` `rrespReg` |
| R valid 延迟 | **`rvalidReg2`** |

**⚠️ `rvalidReg2` 最关键**：
```verilog
assign axi_rvalid = rvalidReg2 & rvalidReg;
```
**⇒ 上电为 X ⇒ 仿真里 Master 会看到 X 的 `rvalid`；FPGA 上是 0。**

**修复后**：`Select-String 'always @\(posedge axi_aclk'` 的 **11 处全部带 `or negedge axi_resetn`**（原先 5 处没有）。

**验证**：iVerilog `PASS: all checks OK`；Questa `Errors: 0, Warnings: 0`。
**⇒ 加了复位后测试仍全过，正说明「FPGA 上本来就是 0，只是仿真里是 X」。**

### 2.2 `video_out`：pclk 域无复位同步器

**报告**：
```
video_out.v:123/188/206/241/298   同一 rst_n 异步复位 clk 与 pclk 两域，全链路无复位同步器
                                  ⇒ "偶尔冷启动花屏、热复位正常"这类难复现故障
```

**机理**：`rst_n` 对 `pclk` 是异步的。**异步断言没问题，异步释放有问题** —— 若 `rst_n` 拉高时贴近 `pclk` 边沿，一部分触发器先脱离复位、另一部分晚一拍，**计数器会从不一致的初值开始。**

**修复**：加两拍移位同步器，`pclk` 域改用 `rst_n_pclk`。

```verilog
reg [1:0] rst_sync_p;
always @(posedge pclk or negedge rst_n) begin
    if (!rst_n) rst_sync_p <= 2'b00;
    else        rst_sync_p <= {rst_sync_p[0], 1'b1};
end
wire rst_n_pclk = rst_sync_p[1];
```

**⚠️ `clk` 域不加**：它与 SoC 同源，`ddr_rstn` 已在那个域同步过。
**⚠️ FIFO 的 `i_arst` 不改**：厂商 `dual_clock_fifo` 内部自带同步。

**验证**：`checks = 95998`（原 95997，多 1）、`errors = 0`、`RESULT: PASS`。
**⇒ 多 1 是预期的**（pclk 域晚 2 拍脱离复位，采样窗口起点差一点），**但数据全对。**

## 三、测试覆盖类

### 3.1 `tb_bitblt_dma_rd`：数据/地址零覆盖

**报告**：
```
★ 数据通路【零覆盖】（dout/dout_valid 接线不用）
★ 地址通路【零覆盖】（araddr/arlen 从不检查）
★ 只信 DUT 自报的 beats_sent，从模型里现成的 beats_recv 被丢弃
```

**代码印证**：
```verilog
20:  wire [AXI_DW-1:0] dout;            ← 接了
55:  .dout (dout),                      ← 连到 DUT
120: beats_recv <= beats_recv + 1;      ← 有计数器
169: else if (beats_sent !== exp_beats)  ← 但只检查 DUT 自报的
```

**修复**：加两项检查。

**① `beats_recv`（模型实收拍数）**
```verilog
end else if (beats_recv !== exp_beats) begin
    $display("FAIL %0s: slave saw %0d beats want %0d", name, beats_recv, exp_beats);
```

**② 数据通路**（模型的 `slv_data = {slv_base[15:0], 8'hA5, slv_cnt}` 带 `8'hA5` 标记）
```verilog
always @(posedge clk) begin
    if (rst_n && dout_valid && dout_ready) begin
        dout_beats = dout_beats + 1;
        if (dout[15:8] !== 8'hA5) dout_bad = dout_bad + 1;
    end
end
```

**验证（注入 DUT 数据通路死亡：`dout <= 0`）**：
```
PASS one-row-2560B: beats_sent=160 beats_recv=160 bursts=1      ← ★ 四项【全过】
PASS multi-burst-8192B: beats_sent=512 beats_recv=512 bursts=2
PASS unaligned-100B: beats_sent=7 beats_recv=7 bursts=1
PASS empty-transfer: beats_sent=0 beats_recv=0 bursts=0
FAIL data path: 682 of 682 beats had no 8'hA5 marker            ← ★ 抓到了
RESULT: FAILED with 1 error(s)
```

**⇒ 这同时印证了报告的两句话**：**「计数对但没搬数据」的 DUT 在前 4 项全过，只有新检查抓到。**

### 3.2 `tb_bitblt_dma_wr`：strobe 检查恒过

**报告**：
```
tb_bitblt_dma_wr.v:282  ★ 末段 strobe 检查等固定 60 拍（不等 done），
                          读的是从不复位的捕获寄存器，而其残留值恰好等于期望值
                          （#3 传输残留 FFFF/FF00 = L294/297 期望）
                          ⇒ 该检查【无论被测行为如何都通过】
```

**代码印证**：
```verilog
291: repeat (60) @(posedge clk);         ← 等固定拍数，不等 done
294: if (cap_strb0 !== {STRB_W{1'b1}})   ← 读从不复位的捕获寄存器
```

**修复**：
```verilog
cap_strb0   = {STRB_W{1'b0}};    // 清残留
cap_strb1   = {STRB_W{1'b0}};
cap_data0   = {AXI_DW{1'b0}};
done_pulses = 0;
... start ...
guard2 = 0;
while (done_pulses == 0 && guard2 < 5000) begin @(posedge clk); guard2 = guard2 + 1; end
```

**验证（注入 DUT 不转发 `strb`：`m_axi_wstrb <= 0`）**：
```
PASS one-row-2560B: beats=160 bursts=1
PASS multi-burst-8192B: beats=512 bursts=2
PASS unaligned-100B: beats=7 bursts=1
PASS empty-transfer: beats=0 bursts=0
```

## 五、`sim.ps1` 的一个副作用（有意保留）

**新判据「无判定即失败」会把 `tb_fifo_latency` 判红** —— **它是测量工具，不产生 PASS/FAIL。**

**⇒ 保留这个严格性**：**漏过一个 FAIL 比误报一个 PASS 危险得多。**
**⇒ 测量型 TB 需要显式豁免**（将来可加 `-ExpectNoVerdict` 参数）。
