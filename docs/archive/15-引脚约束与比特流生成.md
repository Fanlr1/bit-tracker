## 二、⚠️ 关键教训：Efinity 的 flow **是四步，不是三步**

### 错误做法（尝试过，失败两次）

```powershell
efx_run.bat design.xml --flow map
efx_run.bat design.xml --flow pnr     # ← 引脚约束根本没生效
efx_run.bat design.xml --flow pgm
```

**⇒ `pnr` 报 PASS，但 `outflow\` 里【不生成 `pinout.rpt`】** —— **引脚约束被静默忽略**。

**⚠️ 又是「PASS 但不对」** —— 与 [14-整机集成与假PASS教训.md](14-整机集成与假PASS教训.md) 同一类型。

### 正确流程

```powershell
efx_run.bat design.xml --flow map
efx_run.bat design.xml --flow interface   # ★ 必需！处理 .peri.xml
efx_run.bat design.xml --flow pnr
efx_run.bat design.xml --flow pgm
```

**`--flow` 的完整选项**（来自 `efx_run.bat --help`）：
```
map, interface, pnr, pgm, compile, program, rtlsim, mapsim, pnrsim, full, ...
```

### 验证引脚约束是否真的生效

**看 `outflow\<design>.pinout.rpt` 是否生成** —— 不生成就是没生效。

## 四、Interface Designer 报的三个问题（都有明确数值）

`interface` flow 失败时会生成 **`outflow\design_issue.xml`** —— 这是最直接的诊断入口。

### 问题 1（error）：PLL VCO 超出范围

```
HDMI_PLL | pll | error | pll_rule_vco_freq
VCO frequency is out of range. Freq=500.0000  Min=2200MHz  Max=5500MHz.
```

**⇒ 我最初按 `pix_clk(25 MHz) × out_divider(20) = 500 MHz` 配的 VCO 太低。**

**修正**：VCO 取 **2500 MHz**

| 输出 | out_divider | 频率 |
|---|---|---|
| `pix_clk` | **100** | **25.0 MHz** |
| `pix_clk_fast` | **20** | **125.0 MHz** = 5 × 25 |

### 问题 2（error）：bank 3A 必须 1.8 V

```
3A | i/o bank | error | io_bank_rule_lvds
I/O Voltage has to be set to 1.8 V when LVDS Tx is used
```

**⇒ 基底取自 `08`（纯 DDR3 demo），它把 3A 声明为 1.5 V**（那个工程里 3A 只用作 `REF_RES_3A`）。

**修正**：3A 改 **1.8 V LVCMOS**；`3B`/`4A`/`4B` 保持 **1.5 V**。

### 问题 3（warning，不阻塞）：DDR 时钟对距离 LVDS 过近

```
tmds_clk | lvds_tx | warning | lvds_rule_tx_distance
These HSIO GPIO must be placed at least 1 pair away from LVDS tmds_clk:
GPIOR_P_09
```

**`GPIOR_P_09` 正是 DDR3 的 `ddr_ck.P`。**

**⇒ 官方 `02` 工程（HDMI + DDR3 共存）也是同样的布局，说明可接受。**
**⇒ 但记为板上验证的注意点：若 DDR3 初始化不稳定，优先怀疑此处噪声耦合。**

## 五、Efinity PLL 分频公式（反推 + 三处交叉验证）

```
VCO          = 目标输出频率 × 该输出的 out_divider
FB 反馈分频   = VCO / 参考时钟频率        （必须整除）
VCO 范围     = 2200 ~ 5500 MHz           （工具实测报出）
```

**验证依据**（全部来自官方工程的 `timing.rpt` 实测值）：

| 工程 | PLL 参数 | 推算 VCO | 实测输出 |
|---|---|---|---|
| `08` `pll_inst1` | `core_clk` out_div=27 | 100×27 = **2700** | `core_clk` = 100 MHz ✓ |
| `08` `DDR3_PLL` | `clk_100m` out_div=32 | 100×32 = **3200** | 其余 out_div=8 → **400 MHz** ✓ |
| `02` | — | — | `slow`=148.5 / `fast`=742.39 → **正好 5 倍** ✓ |

**⚠️ `multiplier` / `pre_divider` / `post_divider` 不影响这个关系**（推测是 VCO 频段选择），**照抄官方即可，不要试图"修正"**。

### 我们的 HDMI_PLL

```xml
<efxpt:pll name="HDMI_PLL" pll_def="PLL_BR0" ref_clock_name="clk_25m"
    ref_clock_freq="25.0000" multiplier="1" pre_divider="1" post_divider="1"
    locked_name="" is_ipfrz="false" is_bypass_lock="true">
    <efxpt:adv_prop feedback_clock_name="pix_clk" feedback_mode="core"/>
    <efxpt:comp_output_clock name="pix_clk"      number="0" out_divider="100"/>
    <efxpt:comp_output_clock name="pix_clk_fast" number="1" out_divider="20" phase_setting="2"/>
</efxpt:pll>
```

**⇒ PLL 位置不冲突**：`pll_inst1`=`PLL_TL0`、`DDR3_PLL`=`PLL_TR0`、`HDMI_PLL`=`PLL_BR0`（Ti60F225 共 4 个）。

**⚠️ 像素时钟取 25.0 MHz 而非标准的 25.175 MHz** —— 因为 `25.175/25` 不是整数比，反馈分频必须整数。刷新率变为 `25e6/(800×525) = 59.5 Hz`（标准 59.94 Hz），显示器可接受。

## 六、`pix_clk` 为什么不改成内部 wire（目标第 1 条的实际结论）

**原计划**：把 `system_top` 的 `input pix_clk` 改成内部 wire，由 PLL 驱动。

**实际结论：不需要改。** 依据是官方 `03_hdmi_tx_demo` 的写法：

```verilog
module top ( input hdmi_tx_slow_clk, ... );    // 就是一个普通顶层输入端口
    .clk      (hdmi_tx_slow_clk),
    .pixelclk (hdmi_tx_slow_clk),
```

而它的 `.peri.xml` 里 PLL 输出也叫 `hdmi_tx_slow_clk`。

**⇒ Efinity 用「PLL 输出网络与顶层端口同名即连通」处理，端口形式无需改变。**

### 但 RTL 确实改了一处（内容与原计划不同）

**LVDS 段需要 `oe_name` / `reset_name`**，而 `system_top` 原本没有这些端口。**补了 8 个**：

```verilog
output tmds_data0_TX_OE,  output tmds_data0_TX_RST,   // ... data1 / data2 / clk 同理
...
assign tmds_data0_TX_OE = 1'b1;   assign tmds_data0_TX_RST = 1'b0;
```

**⇒ 与官方 `03` 完全一致。**
