# 92 - 慢态尝试：line_start 与 src_started 的双重缺陷（已实现，未确证）

> 接 [docs/90](90-慢态逻辑推理.md)（推理）· [docs/91](91-慢态排查全景（过程记录）.md)（过程）
> 一句话：**定位到两个叠加的缺陷，任修其一都无效，必须同时修——但修复效果未能复现，见 [docs/93](93-首屏调试与双缓冲地址问题.md) 第三节。**

## 一、★ 最终根因

`bitblt_addr_gen` 在 `S_LINE` 等 `line_ack`，而 `line_ack` 需要源读、目标读、写三方都完成。
源读那一侧从未被启动，因为**两个条件同时失效**：

### 缺陷 1：line_start 是一次单脉冲

    bitblt_pulse_gen u_pulse (.level (line_req), .pulse (line_start));

`line_req` 是**电平**（addr_gen 一直保持到 ack），但 `pulse_gen` 只在它的**上升沿**产生一次脉冲。
若那一次 `line_start` 到来时 `dma_rd` 正忙（不在 S_IDLE），这次启动就永远丢失——
`line_req` 保持高，**不会再产生第二个脉冲**。

### 缺陷 2：'只启动一次'用 line_index == 0 判据

    wire src_start = line_start & (~compact_src | (line_index == 0));   // 旧

compact 源只应在第 0 行启动一次，判据写成了 `line_index == 0`。但 `line_index` 在**第 0 行被 ack 后立即递增**，
所以一旦第 0 行错过，这个条件**永远不再成立**。

**两个缺陷互为掩护**：只修缺陷 1（重发），脉冲来了仍被 `line_index==0` 过滤；
只修缺陷 2（latch），没有新脉冲可抓。**两次单独修复都在板上验证为无效**。

## 二、修复（两处同时）

    // 1) 电平保持期间，每 16 拍重发一次 start
    reg [3:0] line_retrig_cnt;
    always @(posedge clk or negedge rst_n)
        if (!rst_n)                     line_retrig_cnt <= 4'd0;
        else if (!line_req || line_ack) line_retrig_cnt <= 4'd0;
        else                            line_retrig_cnt <= line_retrig_cnt + 4'd1;
    wire line_start_retrig = (line_retrig_cnt == 4'd15);
    wire line_start_eff    = line_start | line_start_retrig;

    // 2) '只启动一次'改成 latch，与当前是第几行无关
    reg src_started;
    always @(posedge clk or negedge rst_n)
        if (!rst_n)         src_started <= 1'b0;
        else if (eff_start) src_started <= 1'b0;                    // 新传输清零
        else if (line_start_eff & (~compact_src | ~src_started)) src_started <= 1'b1;

    wire src_start = line_start_eff & (~compact_src | ~src_started);

目标读侧（`dst_start`）有同样的缺陷，同样修法。

**安全性**：`line_index` 在 ack 前不递增，重发永远指向同一行；引擎忙时收到重复 start 只是被忽略。

## 三、实测（板上，单轮）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `hw`（32 精灵硬件路径） | 3,812,172 | **4,191** |
| 单次 blit（`oneblit`） | 3,812,183 | **3,101 / 500** |
| `mon sticky` | `0x00000100`（C_SPR_HANG） | **`0x00000000`** |
| `fsmhist` | 索引 2（`f_src=0`）| **索引 15（`1111`：src 已启动且完成）** |

**提速 1,229 倍**，且 `C_SPR_HANG` 不再触发。

## 四、排查过程中被推翻的假设（按顺序，都留了实测依据）

| # | 假设 | 为何被推翻 |
|---|---|---|
| 1 | DDR 拒绝 AR | `ddr=0x8`：arready=1、arvalid=0，控制器空闲 |
| 2 | 寄存器访问慢 | 正常态 `regacc=17` 拍；慢态下是**表象**，不是原因 |
| 3 | 状态位假报 | 超时瞬间 busy 位确实为高 |
| 4 | walker 空闲 | **采样在超时之后**；直方图显示 32/32 卡在 `S_RUN` |
| 5 | CPU 轮询抢总线 | 退避让 `hw` 从 4.4 亿降到 373 万，但**剩下的 373 万是引擎真的没干活** |
| 6 | AR 仲裁死锁 | `aux=0x0`：仲裁器 IDLE、`Cnl_Search_En=0`，**没有请求** |
| 7 | 中断驱动可解 | 中断要等引擎完成，等的还是同一个时间 |
| 8 | line_start 单脉冲（单独）| 加了重发仍无效——被缺陷 2 过滤 |
| 9 | '只启动一次'判据（单独）| 改成 latch 仍无效——没有新脉冲可抓 |

## 五、两条方法论（比本次修复更值钱）

1. **采样时机决定结论**：帧间空档里一切空闲。要看"卡住"必须在**事件时刻**采样（超时瞬间、或持续状态）。
   本轮多次把"事后空闲"误读为"引擎没工作"，绕了很久。
2. **单点修复无效时，先怀疑"两个缺陷互相掩护"**：本例两个条件互为前提，
   单独验证必然得到"无效"，而结论会误导成"假设错误"。**叠加修复才是正确实验设计**。
