## 三、数据流（一次 BitBlt 拷贝）

```
CPU 写寄存器 (axiA_*)
    │
    ▼
bitblt_axi_slave ──start──► bitblt_addr_gen
    │                            │  每行发一个三元组
    │                            │  (line_src, line_dst, bytes)
    │                            ▼
    │                       line_req/line_ack 握手
    │                            │
    │              ┌─────────────┴──────────────┐
    │              ▼                            ▼
    │      bitblt_dma_rd (源)            bitblt_dma_rd (背景)
    │         bl1_* / S1                   bl2_* / S2
    │              │                            │
    │              └──────────┬─────────────────┘
    │                         ▼
    │              bitblt_pixel_engine (PX_PER_BEAT=4)
    │                         │  128 位 = 4 像素/拍
    │                         ▼
    │                  bitblt_dma_wr
    │                    bl3_* / S3
    │                         │
    └─────────────────────────┴────► Axi_Mux ──► ddr3_top ──► DDR3
```

**⚠️ 关键设计**：**两个读引擎【总是同时启动】**（包括 FILL），**避免模式相关的 valid 选择** —— 代价是每行多一次 DDR 读。

**⇒ 这也让三种新混合模式（ADD/MUL/SCREEN）**免费**拿到了背景数据。**

## 四、寄存器映射（基址 `0xE1000000`）

| 偏移 | 名称 | 说明 |
|---|---|---|
| **0x00** | **CTRL** | **[0] start（自清脉冲）· [1] irq_en · [2] soft_reset** |
| **0x04** | **STATUS** | **只读 · [0] busy · [1] done · [2] error（写错误 或 越界）** |
| **0x08** | **OP** | **0=COPY 1=FILL 2=ALPHA 3=KEYING 4=ADD 5=MUL 6=SCREEN** |
| **0x0C** | SRC_ADDR | |
| **0x10** | DST_ADDR | |
| **0x14** | WIDTH_H | **[15:0] 宽 · [31:16] 高** |
| **0x18** | SRC_STRIDE | 源每行字节数 |
| **0x1C** | DST_STRIDE | 目标每行字节数 |
| **0x20** | FILL_COLOR | ARGB8888 |
| **0x24** | ALPHA | 0..255 |
| **0x28** | KEY_COLOR | ARGB8888 透明色 |
| **0x2C** | FRAME_CNT | 完成的帧数（引擎写） |
| **0x30** | BPP | 每像素字节 1/2/4/8，复位默认 4 |
| **0x34** | **FB_BASE** | **扫描输出基址（复位 0x08000000）** |
| **0x38** | **FB_SIZE_H** | **[15:0] 宽 [31:16] 高（复位 640×480）** |
| **0x3C** | **FB_CFG** | **[15:0] stride（复位 2560）· [16] enable（复位 1）** |

**⚠️ `0x34`/`0x38`/`0x3C` 同时被两处使用**：
- **扫描输出**（`bitblt_video_out`）
- **越界保护的上界**（`bitblt_addr_gen` 的 `fb_start`/`fb_end`）

**⇒ 所以双缓冲切换时，边界自动跟随。**

## 六、时钟域

| 时钟 | 频率 | 约束 | 用途 |
|---|---|---|---|
| **`core_clk`** | **100 MHz** | **10.000 ns** | **SoC + BitBlt 引擎 + AXI** |
| **`sdram_clk`** | **400 MHz** | 2.500 ns | DDR3 |
| **`rx_cal_clk`** | 400 MHz | 2.500 ns | DDR3 校准 |
| **`tx_cal_clk`** | 400 MHz | 2.500 ns | DDR3 校准 |
| **`tx_cal_clk_90edge`** | 400 MHz | 2.500 ns | DDR3 校准 |
| **`pix_clk`** | **25.2 MHz** | **39.680 ns** | **HDMI 像素时钟** |

**⇒ 唯一的跨时钟域**：**`bitblt_video_out` 内部【`clk` ↔ `pclk`】，靠 `async_fifo_gray` 跨越。**

**⚠️ 原先用的是厂商 `dual_clock_fifo_wrapper`，已弃用** —— **它的 `o_empty`/`o_full` 组合依赖 `i_re`/`i_we`，与本设计形成环路（详见 `docs/36`）。** **`dual_clock_fifo.v` 仍在工程文件列表里（供 `tb_fifo_latency` 测延迟），但已不被任何模块例化。**

**⚠️ `pclk` 域有复位同步器**（`rst_sync_p` 两拍），**因为 `rst_n` 对它异步。**

## 七、AXI 通道与 ID 分配

### 7.1 五个从端口

| 端口 | 主设备 | ID | 方向 |
|---|---|---|---|
| **S0** | **SoC（CPU）** | **未知**（`soc.v` 加密）| 读写 |
| **S1** | **BitBlt 读源** | **`8'h18`** | 只读 |
| **S2** | **BitBlt 读背景** | **`8'h1A`** | 只读 |
| **S3** | **BitBlt 写** | **`8'h1C`** | 只写 |
| **S4** | **视频扫描** | **`8'h1E`** | 只读 |

**⚠️ ID 的位宽陷阱**：

```
Axi_Mux 内部 ID 8 位  →  ddr3_top 只接受 4 位
⇒ 【低 4 位被保留，高 4 位丢弃】
⇒ 所以我们的 ID 选在低半字节（8/A/C/E），把 0–7 让给 SoC
```

**⚠️ 这是概率规避，不是保证** —— **`soc.v` 加密，看不到它实际用什么 ID。** **⇒ 板上要跑 1000 次拷贝回读来定性。**

### 7.2 `Axi_Mux` 的两个已知陷阱

| 陷阱 | 机理 | 单主测试能否发现 |
|---|---|---|
| **ID 截断** | **多个主设备并发时数据错乱** | **❌ 不能** |
| **仲裁死锁** | **`Act_Cnl_List` 只在 `M_A_End` 清除；一个主设备中途撤销 `arvalid` 就锁死整个互联** | **❌ 不能** |

**⇒ 这两个都只能靠【多主并发的仿真】验证。**

**⚠️ 2026-10-06 更新：`tb_mux_video` 已跑通（`pixel errors = 0`），但它【只覆盖了 S0（CPU）与 S4（视频）两路并发读】。**

| 端口 | 是否参与 `tb_mux_video` |
|---|---|
| **S0（CPU）** | ✅ **参与（4 拍突发）** |
| **S4（视频）** | ✅ **参与（37 行 × 159 拍）** |
| **S1 / S2（BitBlt 两个读口）** | ❌ **未参与** |
| **S3（BitBlt 写口）** | ❌ **未参与** |

**⇒ 所以「ID 截断」这个陷阱【只被部分覆盖】：S0 与 S4 的 ID（`0x18-ish` 与 `0x1E`）并发时数据投递正确，但 `bl1`/`bl2`/`bl3` 三个口从未与 CPU 同时活动过。** **⇒ 板上仍要按 `21-板上待验清单.md` 的长跑回读来定性。**

## 十、关键设计决策与依据

> **本节合并自 [10-实现计划](10-实现计划.md) §五 与 [12-顶层集成设计](12-顶层集成设计.md) §一（2026-10-07）。**
> **那些文档的其余部分已被实现取代（信号连接表现由 `bitblt_top` 承担），只保留**决策依据**在这里。**

### 10.1 背景像素：两个读引擎并行

**赛题公式 `out = fg×α + bg×(1-α)` 的 `bg` 在 framebuffer 里，必须再读一次 DDR。**

| 方案 | 做法 | 判定 |
|---|---|---|
| **A. 两个读引擎并行** | **一个读源图、一个读目标行，同时喂 M4** | ✅ **选定** |
| **B. 读-改-写 + 行缓冲** | **先读目标行进 BRAM，再读源行** | **串行，慢；还要行缓冲** |

```
640×480@60 × 32bpp            =  73.7 MB/s（单向）
读源 + 读目标 + 写目标         = 221    MB/s
DDR3 可用 = 16 bit × 800 MT/s = 1600   MB/s
⇒ 占用 13.8%
```

**⇒ 带宽绰绰有余，不必为省带宽牺牲流水线。** **⚠️ 但这是 **640×480** 的账。** **⇒ 1080p60 之后扫描输出本身占 594 MB/s（37%），带宽重新变成需要盯的量 —— 见 [40](40-仲裁与HSIO与4KB查证.md)。**

### 10.2 像素并行度：4 像素/拍

**AXI 一拍 128 位 = 4 个 ARGB8888 像素。** **⇒ 若加位宽转换降到 1 像素/拍，吞吐直接掉 4 倍。**

| 方案 | 吞吐 | DSP 用量 | 判定 |
|---|---|---|---|
| **位宽转换 128→32** | **降 4×** | **3** | ❌ |
| **M4 改 4 像素并行** | **满速** | **12（占 160 的 7.5%）** | ✅ **选定** |

### 10.3 帧缓冲：三缓冲而非双缓冲

**⇒ 赛题要求「双缓冲防撕裂」，而 `bank_switch.v` 支持 `FB_NUM=3` 且已有实测地址。** **⇒ 三缓冲更稳（写永不追上读），且满足「≥双缓冲」。**

### 10.4 Alpha 混合用 DSP48；Color Keying 不用

**⇒ 精确 `/255` 需补偿（`>>8` 有 ≤1 LSB 误差）。** **⇒ Color Keying 是纯比较逻辑（`if (pixel == KEY_COLOR) 跳过写`），不需要 DSP。**

### 10.5 DDR3 AXI 互联：四方案对比后选 `Axi_Mux`

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A. `Axi_Mux.v`** ⭐ | **工程自带，128-bit，ID 8-bit** | **参数恰好匹配；就在工程里** | **2777 行从未例化；`include` 路径可能找不到** |
| **B. 官方 `efx_axi_interconnect`** | **IP Manager 生成** | **官方维护、有测例** | **所有 demo 都没用过** |
| **C. tinyml crossbar** | **`axi_interconnect_beta`** | **完整功能（轮询仲裁）** | **是 SV，需改；未在本板验证** |
| **D. 绕开走 `io_ddrMasters_0`** | **32-bit** | **不用写互联** | **只有 32-bit；地址映射未确认** |

**⇒ 最终选 A 并落地为 `Axi_Mux` 的 `X5`（五个从端口全占）。** **⇒ 决策过程见 [11](11-AXI互联方案对比.md)，仲裁行为的查证见 [40](40-仲裁与HSIO与4KB查证.md)。**

## 十一、⚠️ 踩过的坑（实现期记录）

> **这些是**改错会静默失效**的地方，不是历史轶事。**

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| **1** | **`EFX_DSP48` 的 `C[15:0]` 同时是加数【和】右移量** | **结果被移没，且极难查** | **必须 `.SHIFT_ENA(1'b0)`** |
| **2** | **TMDS 输出极性** | **屏幕全黑或无信号** | **`assign tmds_*_o = ~tmds_*`（取反）** |
| **3** | **厂商 demo 的时序参数不一致** | **图像错位、R/B 互换** | **只抄 `lcd_para.v`**（`03`/`09`/`10`/`11` 的都是非标，`10` 的水平还被 `/2`） |
| **4** | **`color_bar_rgb` 必须用 v3.0** | **v2.0 无 `TEST_MODE`** | **v3.0 的 `TEST_MODE=2'b11` 是像素透传，且附送 `h_cnt`/`v_cnt` 像素坐标** |
| **5** | **`bitblt_system.err.log` 是累积的** | **它保留着旧负面测试的错误 ⇒ 会误判当前状态** | **判断当前状态看源文件，不看日志** |
| **6** | **新 RTL 必须登记进 `bitblt_system.xml`** | **iverilog 用 `-y` 搜目录会自动发现，Efinity 只认 xml 列表 ⇒ 仿真过、综合静默漏掉** | **两个地方都要加** |
| **7** | **`map : PASS` 不代表设计正确** | **曾在 map 通过的情况下整机行为错** | **见 [14](14-整机集成与假PASS教训.md)；端到端验证不可省** |

**⇒ 前四条来自 [10](10-实现计划.md) §5.3/§5.6，后三条来自实现期。** **⇒ 完整的过程记录在 [22](22-审计问题修复记录.md) / [23](archive/23-复位与测试覆盖修复.md) / [36](36-tb_mux_video调查结论.md)–[38](38-组合读数组无法映射块RAM.md)。**
