# 133 · 黑屏根因 + 60fps 集成（2026-11-02 夜）

> **黑屏根因已确认**：`dvi_encoder.v` 的输出管道寄存器被一个实验性改动 **bypass** 了
> （源码里就写着 `// EXPERIMENT: pipeline bypassed ...`），TMDS 引脚由编码器组合逻辑直驱
> → 时序报告 `tmds_data*` 路径（pix_clk → pix_clk_fast）slack **-3.7 ns**
> → 与 doc 118 记录的 900 精灵版黑屏**同一个数字**。已恢复打拍。

## 一、黑屏排查结论

| 证据 | 结果 |
|---|---|
| 黑屏时串口 | **完全无输出**（CPU 没跑 → 不只是显示问题）|
| 重烧 bit 后 | 串口恢复、framebuffer 截图有画面 → **内部链路正常** |
| 时序报告 | `tmds_data0[3]~FF|CLK → tmds_data0_o[3]`，launch pix_clk / capture pix_clk_fast，**slack -3.654 ns** |
| 源码 | `assign tmds_data0 = blue;`（未打拍）而不是 `blue_q` —— 打拍逻辑存在但被绕开 |

**修复**：`assign tmds_data{0,1,2} = {blue_q, green_q, red_q}`（doc 118 验证过的版本）。
2 级打拍试过，时序报告无变化（这条违例是 pix_clk→pix_clk_fast 的跨域检查，118 里同样 -3.7 而板子可正常工作），故回到 1 级。

## 二、60 fps 改动（已集成，仿真全 PASS）

| 模块 | 改动 | 仿真 |
|---|---|---|
| `gfx_core.v` | 新增 `OP_COPY_KEY_NB = 3'd6`：**不读背景**、key 像素掩码写（不写）、非 key 写 f | `tb_core_nb.v` 5/5 PASS（key 像素 0 写、rd2_req=0、边界裁剪、COPY_KEY/FILL 回归）|
| `gfx_sprtab.v` | 表项 bit31 = TRANSP（0→op6 / 1→op4），y 用 bit26:16（11 位）| `tb_sprtab.v` 40 PASS |
| `main.c` | 写表时后 1/4 精灵置 TRANSP（与稳定版观感一致）| — |
| 联仿 | `tb_tab_core2.v`：walker→core 集成 | PASS：op6 精灵 **rd2=0、8 写**（稳态 16 事务/精灵）、op4 精灵 24 事务；像素级正确 |

**事务预算**：3000 不透明×17 + 1000 半透明×24 = 75000 事务/帧（原 96000）→ 理论 **46–56 fps**。

## 三、集成后的新问题：PnR 布局抽签决定 scan-out 饥饿

集成版第一次构建（seed 3）实测：

| 指标 | 值 | 说明 |
|---|---|---|
| fps | 34.8（反而降）| |
| **tabspin** | **53952**（原 101800）→ 引擎时间减半 ✅ | op6 确实生效 |
| CPU | 16.9 ms（原 28.1）✅ | |
| **under** | **77696 累计（≈50/帧）** | ❌ scan 饥饿 |
| **shown** | **0**（画面冻结/黑屏）| ❌ |

**AB 对照实验**：把 flag 全置 1（全部走旧 OP_BLIT，op6 完全不参与）→ **仍然 shown=0、under 6 万**。
⇒ **不是 op6 的掩码写问题**，而是这次 PnR 布局（seed 3）本身让 scan-out 抢不到 DDR —— 与 11-01 的 seed 2（shown=0）同款抽签现象。

**正在做**：对集成版 RTL 扫 seed（5/7/9/11/13），判据：fps>40 且 under/帧<15 且 shown 持续增长。
结果写 `work/logs/seed-op6.log`。
