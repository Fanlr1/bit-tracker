## 一、模块职责

**AXI4 从设备 + 寄存器组**，挂在 Sapphire SoC 的 **`0xE1000000`** 窗口（16 MB / 32-bit / 支持突发）。

**结构照抄官方 `axi4_slave.v`**（端口与 `soc.v:487-526` 严格对齐），**把 4 KB BRAM 换成 16 字寄存器组**（实用 12 个）。

### 寄存器映射

| 偏移 | 名称 | 说明 |
|---|---|---|
| `0x00` | `CTRL` | [0] start（自清脉冲）[1] irq_en [2] soft_reset |
| `0x04` | `STATUS` | [0] busy [1] done [2] error —— **只读**，由引擎驱动 |
| `0x08` | `OP` | 0=COPY 1=FILL 2=ALPHA 3=KEYING |
| `0x0C` | `SRC_ADDR` | 源基址 |
| `0x10` | `DST_ADDR` | 目标基址（framebuffer）|
| `0x14` | `WIDTH_H` | [15:0] 宽 [31:16] 高 |
| `0x18` | `SRC_STRIDE` | 源行跨度（字节）|
| `0x1C` | `DST_STRIDE` | 目标行跨度 |
| `0x20` | `FILL_COLOR` | ARGB8888 |
| `0x24` | `ALPHA` | 全局 alpha 0~255（复位默认 `0xFF`）|
| `0x28` | `KEY_COLOR` | 透明色（复位默认品红 `0xFF00FF`）|
| `0x2C` | `FRAME_CNT` | 完成帧计数 |

## 四、⚠️ 继承的 AXI 非标准之处（务必知晓）

这三条**来自官方模板**，我**故意保留**（官方设计已在 SoC 上验证通过，擅自"修正"反而有风险）：

| # | 问题 | 影响 |
|---|---|---|
| 1 | **读写互斥**（单 4 态状态机） | 不能同时读写；对寄存器访问够用 |
| 2 | **AW 与 W 必须同拍有效**（`axi_awready` 的生成条件）| 标准 AXI 允许 AW 先到，某些 master 可能不兼容 |
| 3 | **`axi_rvalid` 组合依赖 `axi_rready`**（违反 AXI 规范，可能死锁）| 对 VexRiscv 实测可用；**别把这个模式抄到别处** |

**⇒ 如果将来换成别的 AXI master、或出现读挂死，优先查第 3 条。**

## 五、与 M4 的对接（下一步）

```
soc.axiA_*  ──> M1 (寄存器) ──reg_* ──> M3 (地址生成) ──> M5 (DMA)
                    ▲                                          │
                    └──────────── reg_status ◄─────────────────┘
```

**M1 输出的 `reg_start_pulse` 将驱动 M3 启动一次渲染**；`reg_status` 由 M5 在完成时回写。
