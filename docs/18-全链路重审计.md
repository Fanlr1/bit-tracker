## 三、维度 1：地址一致性 ✅

### 地址区间（逐项算过，非估算）

```
FB A : 0x08000000 .. 0x0812BFFF   (1228800 B)
FB B : 0x0812C000 .. 0x08257FFF   (1228800 B)
SPR  : 0x09000000 .. 0x09003FFF   (16384 B)
程序 : 0x00001000 .. 0x0001FFFF   (124 KB, 链接脚本 ram 区间)

FB B 末端到 SPR 间隙 : 14319616 B   → 不重叠
程序区上界 0x0001FFFF < FB A 0x08000000 → 不冲突
```

### 驱动与 RTL 的值对照

| 项 | 驱动 (`main.c`) | RTL (`bitblt_axi_slave.v` 复位默认) |
|---|---|---|
| **基址** | `FB_BASE = 0x08000000` | `r_fb_base = 32'h0800_0000` |
| **宽高** | 640 × 480 | `r_fb_size_h = 32'h01E0_0280`（h480 w640）|
| **stride** | `640*4 = 2560` | `r_fb_cfg[15:0] = 0x0A00 = 2560` |
| **enable** | — | `r_fb_cfg[16] = 1` |

**⇒ 逐位一致。**

### ⚠️ 一个被排除的可疑项

`soc.h` 里 `SYSTEM_DDR_BMB = 0x1000` / `SIZE = 0xe0000000`（3.5 GB），
**而 DDR3 只有 256 MB** ⇒ 说明该宏**不是 CPU 视角的物理地址**，而是 BMB 总线窗口偏移。

**间接证实**：链接脚本把程序放在 `0x00001000`，而它跑在 DDR 里 ⇒ **CPU 视角的 DDR 从 0 开始** ⇒ `0x08000000` 在 DDR3 内。

## 四、维度 2：像素格式 ✅

```
驱动写      : ARGB(0xFF,r,g,b) = 0xFF_RR_GG_BB
视频取低24位 : px_sel = hold[23:0] = 0xRRGGBB
system_top  : vid_rgb[23:16] → red_din
              vid_rgb[15:8]  → green_din
              vid_rgb[7:0]   → blue_din
```

**⇒ `0xRRGGBB` 的字节序与 RGB 拆分完全吻合。**

**⚠️ 这一维特别值得查**：颜色错了**不会报任何错**，只会看到画面偏色 —— 很容易被误判成"编码器坏了"或"显示器问题"。

## 六、🚨 维度 3：AXI ID 冲突（**本次审计最重要的发现**）

### 证据链

```
Axi_Mux.v:417   parameter SLAVE_ID_WIDTH = 8
Axi_Mux.v:423   localparam MASTER_ID_WIDTH = (ID_MODE_SEL == "Normal")
                                            ? SLAVE_ID_WIDTH : ...
Axi_Mux.v:437   localparam MIW = MASTER_ID_WIDTH          ⇒ MIW = 8

ddr3_parameter.vh   `define AXI_ID_WIDTH  4
ddr3_top.v:46       parameter AXI_ID_WIDTH = `AXI_ID_WIDTH
ddr3_top.v:103      input [AXI_ID_WIDTH-1:0] s_axi_awid    ⇒ 4 位
system_top.v:182    wire [AXI_ID_WIDTH-1:0] s_axi_awid     ⇒ 4 位
```

**⇒ `Axi_Mux` 输出 8 位 ID 接到 4 位端口，Verilog 静默取低 4 位。**

### 截断后的实际 ID

| 主机 | 原 8 位 | **低 4 位** | 修改后 |
|---|---|---|---|
| BitBlt 读源 | `8'h10` | `0x0` | 保持 |
| BitBlt 读目标 | `8'h12` | `0x2` | 保持 |
| BitBlt 写 | `8'h14` | `0x4` | 保持 |
| **视频读** | ~~`8'h20`~~ | ~~`0x0`~~ 🚨 | **`8'h16` → `0x6`** ✅ |

**⇒ 视频读与 BitBlt 读源原本共用 ID `0x0`，已修。**

### 为什么这是真问题

**AXI ID 的作用是让 Master 区分【并发事务】的响应。**
`Axi_Mux` 内部有 `Axi_Mux_Wr_Ctrl` / `Rd_Ctrl` / `Addr_Ctrl` / `Info_Fifo` —— **这些正是为多通道并发而存在的**。

**⇒ 两个主机用同一 ID，DDR3 返回的响应无法区分 ⇒ 读数据可能串台。**

### ⚠️ 为什么前面的测试都没抓到

| 测试 | 为什么漏掉 |
|---|---|
| **单元测试** | 只测 M1 单模块，没有多个主机 |
| **端到端** | 只有 BitBlt 三个引擎（ID 本就错开），**视频通路不在这个 TB 里** |
| **整机综合** | 综合不检查 AXI 协议的语义 |
| **仿真** | **AXI 协议允许 ID 重复**，不报错 |

**⇒ 只有【交叉核对位宽】才能发现。这正是本次审计的价值。**

### ⚠️ 仍未解决的部分：**SoC 的 ID 不可控**

```
soc.v   output [7:0] io_ddrA_aw_payload_id;
        output [7:0] io_ddrA_ar_payload_id;
```

**SoC 的 ID 也是 8 位，同样被截断到低 4 位。**
**如果 SoC 从 `0x0` 开始递增 ID（AXI Master 的常见做法），就会与 BitBlt 读源冲突。**

**⇒ 建议启用 `ID_MODE_SEL = "Extend"`**（M 侧 ID = S 侧 ID + 通道号），
**但【未经仿真验证】，不知道截断后保留哪几位，不能直接改。** 需先仿真确认。

## 七、维度 4：中断链路 ✅ 接通，⚠️ 一项存疑

### 链路逐环确认

```
bitblt_top.axi_interrupt                              （输出）
  ↓  system_top:994  .axi_interrupt (blt_interrupt)
  ↓  system_top:362  wire blt_interrupt;
  ↓  system_top:672  .axiAInterrupt (blt_interrupt)   ← SoC 例化
soc.v  system_axiA_interrupt_plic_gateway_ip <= axiAInterrupt;
  ↓
soc.h  #define SYSTEM_PLIC_SYSTEM_AXI_A_INTERRUPT 30
  ↓
驱动   plic_set_enable(..., SYSTEM_PLIC_SYSTEM_AXI_A_INTERRUPT, 1)
```

**⇒ 四环全部对齐，PLIC ID 30 一致。**

### ✅ 排除了「中断风暴」

```verilog
// bitblt_addr_gen.v
41:  output reg done,            // one-cycle pulse
77:  done <= 1'b0;               // default: pulse only
86:  done <= 1'b1;               // 仅两处置位
132: done <= 1'b1;
```

**⇒ `done` 是单周期脉冲，不是电平。** 不会出现「ISR 结束立刻又进 ISR」的死循环。

### ⚠️ 但暴露出相反的风险：**脉冲可能太窄**

```
done 宽度 = 1 个 core_clk = 10 ns
soc.v: system_axiA_interrupt_plic_gateway_waitCompletion <= axiAInterrupt;
```

**`waitCompletion` 这个信号名提示 gateway 可能要求中断线【保持到被应答】** ——
**若是，10 ns 脉冲会丢失。**

**⇒ `soc.v` 加密，无法从内部确认。**

### 缓解措施（已内置）

驱动里的等待是**有界的**：

```c
uint32_t guard = 0;
while (!g_done_irq && guard < 10000000u) { guard++; }
if (!g_done_irq) {
    bsp_printf("WARNING: no done interrupt within guard (frame %u)\r\n", f);
    break;
}
```

**⇒ 即使中断收不到，程序也不会卡死，会打印警告后继续。**

**⇒ 判定：可接受。板上第一件事就是看这条 WARNING 有没有出现。**

## 八、维度 5：位宽匹配 ✅

| 信号 | `Axi_Mux` 侧 | DDR3 侧 | 判定 |
|---|---|---|---|
| **数据** | 128 位 | 128 位 | ✅ 一致 |
| **strb** | 16 位 | 16 位 | ✅ 一致 |
| **地址** | 32 位 | **28 位** | ✅ **安全**（见下）|
| **ID** | 8 位 | **4 位** | 🚨 见维度 3 |

### 地址截断安全性（逐项核对）

```
FB A       0x08000000   < 0x0FFFFFFF  OK
FB B       0x0812C000   < 0x0FFFFFFF  OK
FB B 末端   0x08258000   < 0x0FFFFFFF  OK
SPR        0x09000000   < 0x0FFFFFFF  OK
```

**⇒ 全部落在 28 位范围内，截断不会导致地址回绕。**
