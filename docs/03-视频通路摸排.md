## 一、视频输出通路

### 1.1 硬件通路（物理层）

```
FPGA 内部                      IO 原语                    板卡
─────────                     ────────                   ─────
dvi_encoder / rgb2dvi  ──►  LVDS_TX 差分对 (serial_width=10,
  txc_o[9:0]                   is_half_rate=true,
  txd0_o[9:0]                  diff_type="lvds")
  txd1_o[9:0]                       │
  txd2_o[9:0]                       ▼
                            GPIOR_PN_10 / _11 / _12 / _13  ──►  HDMI 连接器
```

- **不是**用 Efinix 的专用 TMDS 原语，而是 **LVDS 差分对 + 自写 10:1 串化器**（`is_half_rate=true` + `serial_width=10`）。
- `GPIOR_PN_10` 一组的 `is_half_rate=true` 表示 slow_clk 供 2 个 bit，fast_clk 供 5 个 bit，合起来 10 bit。

### 1.2 逻辑通路（三个不同实现）

#### A. 03_hdmi_tx_demo —— 纯彩条（最简单，无 DDR）

```
color_bar_rgb(TEST_MODE=2'b10 彩条)  ──►  dvi_encoder  ──►  LVDS_TX (10bit) ──► HDMI
   hs/vs/de + RGB888                      3× encode(8b→10b)      取反后输出
```

#### B. 09_hdmi2dsi_Demo —— HDMI 进 → DDR → 出到 MIPI DSI（**最完整**）

```
HDMI RX ──► dvi_decoder ──► frame_buffer ──► pixcel_122(1→2 像素) ──► dsi_tx ──► MIPI 屏
  LVDS_RX      TMDS 解码      ├ ddr_wr_buffer ──► ddr3_top ──┐        48bit/2pix
  PN_19/16/18/17  →R/G/B      └ ddr_rd_buffer ◄──────────────┘        RGB888
                                (bank_switch 三缓冲)
```

#### C. 10_Ti60f225_sc431hai2hdmi_demo —— 摄像头进 → DDR → 出到 HDMI

```
SC431HAI ──► csi_rx_controller ──► frame_buffer ──► debayer_top_2to1 ──► dvi_encoder ──► HDMI
 MIPI CSI      64bit @50MHz        ├ 写 32bit/px     RAW→RGB888          3× encode
 4 lane        取[9:2]得 MSB8      └ 读 16bit/px     (2像素/时钟)
```

### 1.3 HDMI TX 引脚分配（三 demo 一致，**确认**）

| 信号 | 封装引脚 | 方向 | 证据 |
|---|---|---|---|
| TMDS CLK | `GPIOR_PN_10` | tx | `03\...\hdmi_tx.peri.xml:116`；`02\...\DDR3_MC.peri.xml:519`；`10\...\ti60f225_oob.peri.xml:405` |
| TMDS D0 | `GPIOR_PN_13` | tx | `03:127`；`02:530`；`10:416` |
| TMDS D1 | `GPIOR_PN_11` | tx | `03:138`；`02:541`；`10:427` |
| TMDS D2 | `GPIOR_PN_12` | tx | `03:149`；`02:552`；`10:438` |

> **注意通道映射坑**：`03` 的 `dvi_encoder` 把 `tmds_data0=blue, data1=green, data2=red`；`10` 顶层把 `i_bdata` 接到红色变量、`i_rdata` 接到蓝色变量（`10\...\rtl\ti60f225_oob_top.v:963-965`）。**换 demo 时必须实测颜色顺序**，否则会 R/B 互换。

### 1.4 HDMI RX 引脚分配（**仅 demo 02 与 09 有**）

| 信号 | 封装引脚 | 出处 |
|---|---|---|
| HDMI RX CLK | `GPIOR_PN_19` | `02\...\DDR3_MC.peri.xml:439`；`09\...\ti60f225_demo.peri.xml:399` |
| HDMI RX D0 | `GPIOR_PN_16` | `02:459`；`09:419` |
| HDMI RX D1 | `GPIOR_PN_18` | `02:479`；`09:439` |
| HDMI RX D2 | `GPIOR_PN_17` | `02:499`；`09:459` |
| HDMI SCL | `GPIOR_P_14` | `02\...\DDR3_MC.peri.xml:85` |
| HDMI SDA | `GPIOR_N_14` | `02\...\DDR3_MC.peri.xml:90` |
| HDMI 5V 检测 | `GPIOR_P_15` | `02\...\DDR3_MC.peri.xml:95` |
| HPD | `GPIOR_N_15` | `02\...\DDR3_MC.peri.xml:98` |

> 结论：**HDMI RX 与 TX 用完全不同的引脚组**（RX 在 PN_16~19，TX 在 PN_10~13），板上应是**两个独立 HDMI 口**，可同时收 + 发。

## 二、视频输入通路

### 2.1 摄像头硬件通路（MIPI CSI-2 D-PHY）

```
SC431HAI / IMX219
   │  MIPI CSI-2
   ▼
MIPI D-PHY RX 硬核  ──► csi_rx_controller (Efinix IP)  ──► 像素数据
 cam_ck = GPIOT_PN_09                                  (64bit 并行)
 cam_d0 = GPIOT_PN_07
 cam_d1 = GPIOT_PN_10
 cam_d2 = GPIOT_PN_06
 cam_d3 = GPIOT_PN_11
```
出处：`07\...\ti60f225_oob.peri.xml:511,533,555,577,599`；`10\...\ti60f225_oob.peri.xml:553,575,597,619,641`

- **4 lane RX**，`GPIOT_PN_*` bank（与 HDMI 的 `GPIOR_PN_*`、DSI 的复用组分离）
- csi_rx_controller 输出：`pixel_data[63:0]` + `pixel_data_valid` + `hsync_vc0` + `vsync_vc0`

### 2.2 像素格式（**关键，易错**）

`07` 与 `10` 的顶层都做了**同一个手工解包**：

```verilog
// 10\...\rtl\ti60f225_oob_top.v:511  (= 07\...\rtl\ti60f225_oob_top.v:582)
.i_de (w_mipi_rx_de & w_mipi_rx_hs),
.vin  ({w_mipi_rx_data[39:32], w_mipi_rx_data[29:22],
        w_mipi_rx_data[19:12], w_mipi_rx_data[9:2]}),
```

| 项 | 值 | 说明 |
|---|---|---|
| MIPI 包内格式 | **RAW10**（每像素 10 bit 打包） | 取 `[9:2]` = 丢弃低 2 bit，保留 **MSB 8 bit** |
| 取出步长 | 每像素跨 **10 bit** | `9:2` → `19:12` → `29:22` → `39:32` |
| 送进 frame_buffer 的宽度 | `I_VID_WIDTH = 32`（4 像素/时钟） | `10\...\ti60f225_oob_top.v:491` |
| pixel clock | `i_mipi_rx_pclk` = **50 MHz** | `10\...\ti60f225_oob.sdc:21`（period 20.0） |

> **注意**：这是 **Raw10→MSB8 的截断（truncation），不是标准 RAW8**。原 10 bit 的低 2 bit 被直接丢弃 ⇒ 亮度分辨率降为 8 bit，且没有做 10→8 的舍入。
> **另一坑**：`frame_buffer` 的 `O_VID_WIDTH` 声明 16，但顶层实际接了 **24 bit**（`{ch0_g, ch0_b}`，两路 8bit）⇒ 端口宽度与实参不匹配（靠 Verilog 宽松位宽通过）。复用时必须自己统一。

### 2.3 三个输入源对比

|来源|接口|像素格式|通路|
|---|---|---|---|
|SC431HAI（demo 07/10）|MIPI CSI-2 4lane|RAW10（取 MSB8）|csi_rx_controller → frame_buffer|
|HDMI 输入（demo 02/09）|TMDS over LVDS|RGB888（TMDS 解码后）|dvi_decoder → frame_buffer|
|IMX219（`参考资料\Demo\...\IMX219_HDMI_1080P`）|MIPI CSI-2 4lane|RAW8 → `VIP_RAW8_RGB888` 硬件 debayer|MIPIRx4LaneFre/csi_rx → axi4_ctrl → DDR|

### M1 `color_bar_rgb` —— 纯视频时序发生器（★★★ 首选）

| 项 | 内容 |
|---|---|
| **路径** | `<DEMO>\03_hdmi_tx_demo\hdmi_tx_demo_v2\rtl\color_bar_v3.0\color_bar_rgb.v` |
| 副本 | `02\...\source\hdmi_src\color_bar_rgb.v`；`07\...\rtl\color_bar_v3.0\color_bar_rgb.v`；`09\...\color_bar_v2.0\color_bar_rgb.v`；`11\...\src\color_bar_v2.0\color_bar_rgb.v` |
| 官方文档 | `07\...\rtl\color_bar_v3.0\video IP说明.docx`（见下方摘录） |
| 大小 | 361 行（v3.0） |

**参数**（`color_bar_rgb.v:3-19`）：

```verilog
module color_bar_rgb #(
    parameter DYN_EN       = 1'b0,       // 动态使能
    parameter HS_POLORY    = 1'b1,       // HS 极性
    parameter VS_POLORY    = 1'b1,       // VS 极性
    parameter SYMBOL_WIDTH = 'd10,       // 每分量位宽（用 8）
    parameter SYMBOL_NUM   = 'd3,        // 分量数（RGB=3）
    parameter PAR_PIXEL_NUM= 'd1,        // 每时钟像素数（1/2/4）
    parameter HFP = 13'd100,             // 行前肩
    parameter HST = 13'd100,             // 行同步宽（= HSPW）
    parameter HACT= 13'd384,             // 行有效
    parameter HBP = 13'd100,             // 行后肩
    parameter VFP = 13'd4,
    parameter VST = 13'd5,               // 场同步宽（= VSPW）
    parameter VACT= 13'd288,
    parameter VBP = 13'd4,
    parameter TEST_MODE = 2'd0
)(
    input  wire clk,
    input  wire rst_n,
    input  wire [PAR_PIXEL_NUM*SYMBOL_NUM*SYMBOL_WIDTH-1:0] i_cfg_vid,  // ★ 外部像素输入
    output reg [15:0] h_cnt,     // 当前列
    output reg [15:0] v_cnt,     // 当前行
    output reg        hs,
    output reg        vs,
    output reg        de,
    output reg [PAR_PIXEL_NUM*SYMBOL_NUM*SYMBOL_WIDTH-1:0] o_vid_data
);
```

**TEST_MODE 解码表**（`color_bar_rgb.v:181-325` + `video IP说明.docx`）：

| TEST_MODE | 行为 | 代码行 |
|---|---|---|
| `2'b00` | 递增数据（彩条测试） | `:182-191` |
| `2'b01` | 每帧换色的 EBU 彩条 | `:192-288` |
| `2'b10` | 静态彩条 | `:289-313` |
| **`2'b11`** | **透传 `i_cfg_vid` → `o_vid_data`** | **`:315-324`** |

**★ 用法（我们要的用法）**：设 `TEST_MODE = 2'b11`，则

```verilog
always @(posedge clk) o_vid_data <= i_cfg_vid;   // :321
```
即「我喂什么像素，它就按 hs/vs/de 时序吐出来」。**这正是「从内存/FIFO 读像素 → 生成视频时序」的那一环。**

```verilog
color_bar_rgb #(
    .HS_POLORY(1'b1), .VS_POLORY(1'b1),
    .SYMBOL_WIDTH(8), .SYMBOL_NUM(3), .PAR_PIXEL_NUM(1),
    .HFP(88), .HST(44), .HACT(1920), .HBP(148),   // 1080p60 标准
    .VFP(4),  .VST(5),  .VACT(1080), .VBP(36),
    .TEST_MODE(2'b11)                              // ★ 透传模式
) u_timing (
    .clk(pixel_clk), .rst_n(rst_n),
    .i_cfg_vid({fb_r, fb_g, fb_b}),   // ★ 你的 framebuffer 输出
    .hs(video_hs), .vs(video_vs), .de(video_de),
    .o_vid_data({video_r, video_g, video_b}),
    .h_cnt(), .v_cnt()                // 可留空，或用于算 framebuffer 地址
);
```

> **`h_cnt`/`v_cnt` 天然就是「当前像素坐标」**，可直接当 framebuffer 读地址用（BitBlt 引擎的 src/dst 坐标正好需要它）。这是**双份收益**。

⚠️ **版本差异**：`11` 里的 `color_bar_rgb.v` 是 **v2.0**，端口是 `i_rdata/i_gdata/i_bdata` + `rgb_r/rgb_g/rgb_b`（见 `11\...\src\color_bar_v2.0\color_bar_rgb.md`），**没有 TEST_MODE**。要透传必须用 **v3.0**。

### M2 `data_tx` —— 带 FIFO 的视频时序发生器（★★★ 已和 DDR 打通）

| 项 | 内容 |
|---|---|
| **路径** | `07\...\rtl\frame_buffer\data_tx.v`（437 行） |
| 副本 | `09\...\src\frame_buffer\data_tx.v` |

```verilog
module data_tx #(
    parameter VID_WIDTH = 16,
    parameter FIFO_DIPTH = 512,
    parameter FIFO_ALMOST_FULL = 240
)(
    input  wire clk, rst_n,
    input  wire frame_en,
    input  wire [VID_WIDTH-1:0] fifo_wr_data,   // ★ FIFO 写数据
    input  wire fifo_wr_en,
    output reg  fifo_wr_almost_full,            // ★ 反压
    output reg  fifo_rd_period,                 // ★ 帧周期标志
    output reg  fifo_rd_underflow,
    input  wire [12:0] H_FRONT_PORCH, H_SYNC, H_VALID, H_BACK_PORCH,
    input  wire [12:0] V_FRONT_PORCH, V_SYNC, V_VALID, V_BACK_PORCH,
    output reg  [VID_WIDTH-1:0] vout,           // ★ 按 de 输出的像素
    output reg  o_hs, o_vs, o_de
);
```

- **与 M1 的区别**：M1 是纯时序发生器（像素由外部组合逻辑给）；M2 **内含 DC_FIFO**，自己按 de 从 FIFO 取像素 ⇒ **更接近「从 FIFO 读 → 出时序」**。
- `fifo_rd_period` 每帧给出一个脉冲，`frame_buffer.v:197` 用它触发 DDR 读起始地址归零 ⇒ **天然的帧同步信号**。
- 行状态机：`S_H_SYNC→S_H_BACK_PORCH→S_H_VALID→S_H_FRONT_PORCH`（`:38-45`）。

### M3 `frame_buffer` —— DDR ↔ 视频流桥 + 多缓冲（★★★ 最完整）

| 项 | 内容 |

| **路径** | `07\...\rtl\frame_buffer\frame_buffer.v`（352 行） |

    parameter AXI_ADDR_WIDTH = 33,

    parameter BURST_LEN     = 8'd15,
    parameter FB_NUM        = 3,          // ★ 缓冲个数 1/2/3
    parameter MAX_VID_WIDTH = 1920,
    parameter MAX_VID_HIGHT = 1080
)(
    input  axi_clk, rst_n,
    // ── 写入侧（视频源）
    input  i_clk, i_vs, i_de,
    input  [I_VID_WIDTH-1:0] vin,
    // ── 读出侧（显示）
    input  o_clk,
    output o_hs, o_vs, o_de,
    output [O_VID_WIDTH-1:0] vout,
    // ── 时序参数（透传给内部 data_tx）

    // ── full AXI4
    output [5:0] awid, output [AXI_ADDR_WIDTH-1:0] awaddr, output [7:0] awlen, ...
    output [5:0] arid, output [AXI_ADDR_WIDTH-1:0] araddr, output [7:0] arlen, ...
    output [AXI_DATA_WIDTH-1:0] wdata, ...
    input  [AXI_DATA_WIDTH-1:0] rdata, ...
    // ── 调试

### M4 `bank_switch` —— 1/2/3 缓冲地址切换（★★ 直接抄）

module bank_switch #(

**三种模式**（`generate` 分支）：

| FB_NUM | 行为 | 行号 | 适用 |
|---|---|---|---|
| 1 | 读写同一 bank（`wr_bank=rd_bank=0`）| `:42-61` | 无撕裂要求 |
| **2** | **乒乓**：`wr_sw & rd_sw` 同时有效才切换（注释原文「必须两个bank同时切换」）| `:62-96` | **赛题够用** |
| **3** | **三缓冲**：`dirt_bank`/`clean_bank` 状态机，写指针永远不追上读指针 | `:97-159` | **最稳，推荐** |

- 帧长自动计算：`FRAME_LEN = MAX_VID_WIDTH*MAX_VID_HIGHT*VID_DATA_WIDTH/8 + 32'h200`（`:32`）
- 三缓冲地址：`FRAME_1ST=START`；`FRAME_2ND=FRAME_LEN+START`；`FRAME_3RD=FRAME_LEN+FRAME_2ND`（`:34-37`）

**实测地址（1920×1080×3 字节/像素）**——来自官方调试文档 `10\...\rtl\frame_buffer\调试总结 .docx` 提取：

```
三个 bank 的切换地址，分别为
  0x000000
  0x005EEE00
  0x00BDDC00        (= 0x5EEE00 × 2)
```
`0x5EEE00 = 6,221,568 = 1920 × 1080 × 3` ⇒ **确认：每个 bank 恰好存一帧 RGB888**。

**`ddr_rw_ctrl.v`（`...\src\ddr_rw_ctrl.v`，340 行）——第二套三缓冲实现**：

```verilog
module ddr_rw_ctrl (
    input  ddr_clk, ddr_rst,
    // DDR 写
    input  ddr_wr_busy,  output [127:0] ddr_wr_data,
    output [15:0] ddr_wr_mask, output [31:0] ddr_wr_addr,
    output reg ddr_wr_en, input ddr_wr_ack,
    // DDR 读
    input  ddr_rd_busy,  output [31:0] ddr_rd_addr,
    output reg ddr_rd_en, input [127:0] ddr_rd_data,
    input  ddr_rd_valid,
    // 写帧（视频源侧）
    input  wframe_pclk, wframe_vsync, wframe_data_en,
    input  [63:0] wframe_data,
    // 读帧（显示侧）
    input  rframe_pclk, rframe_vsync, rframe_data_en,
    output [15:0] rframe_data
);
parameter C_BURST_LEN   = 32;
parameter C_RD_END_ADDR = 38400;    // 1024*600/16
```

| 机制 | 实现 | 行号 |
|---|---|---|
| 三缓冲索引 | `wframe_index` 0→1→2→0；`rframe_index = wframe_index-1`（wr=0 时 rd=2）| `:161-199` |
| 地址拼接 | `ddr_wr_addr = {wframe_index, waddr}`；`ddr_rd_addr = {rframe_index, raddr}` | `:307, :325` |
| 状态机 | `S_IDLE→S_WRITE/S_READ→S_FINISH`（写优先，读空闲时插入）| `:203-247` |
| 跨时钟 FIFO | `W0_FIFO`（wframe_pclk→ddr_clk）、`R0_FIFO`（ddr_clk→rframe_pclk）| `:122, :142` |
| 门限 | 写：`wfifo_rcnt >= 32`；读：`raddr < C_RD_END_ADDR && rfifo_wcnt < 64` | `:223-226` |

> 对比：`frame_buffer`（M3）是**通用 AXI4 版**，`ddr_rw_ctrl` 是**绑定特定 DDR 用户接口（a/w/r/busy）的轻量版**。**推荐用 M3**（AXI4 标准，易挂 RISC-V）。
