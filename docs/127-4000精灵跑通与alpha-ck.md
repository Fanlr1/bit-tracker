## 二、两遍扫描（画面正确性关键）

原状态机是「每精灵：擦旧位置 → 画新位置」交织。4000 个重叠精灵时，
精灵 i+1 的擦除（实心背景色 fill）会把精灵 i 刚画的像素打洞 → 画面撕裂。

改为 **先全部擦除，再全部绘制**（phase 0/1 两遍扫描同一张表）：
- 命令序：4000×FILL → 4000×BLIT（`spprog=8000` 上板实测确认）
- 代价：表在 BRAM，多读一遍零成本
- 仿真 `tb_sprtab`：先 2×op=0(FILL) 再 2×op=4(BLIT) ✅

## 三、alpha+ck（用户要求「alpha + ck」）

引擎本就有 `OP_BLIT = (f==key) ? b : mix565(f,b,alpha)`（key 去背 + alpha 混合）。
改动：
- 遍历器绘制命令 op 从 `1(COPY)` → **`4(OP_BLIT)`**，填 `cmd[103:96]=alpha`
- 新增寄存器 `R_SPRALPHA=0xA8`（gfx_regs → 遍历器 `alp` 端口）
- 固件表路径写 `G_SPRALPHA=200`（200/255 混合）
- 仿真 `tb_sprtab` 实测：`op=4 ... alp=128`（tb 灌 128）✅

## 五、fps 30 的根因（已定位）

片上 RAM 只有 **124 KB**（`default.ld: LENGTH=124K`），4000 精灵装不下：
- g_bx/by/bvx/bvy：4×4000×2 = 32 KB
- g_old_x/g_old_y（双缓冲×2 坐标）：2×2×4096×2 = 32 KB
- 其它（g_rb 9.6K、g_sep 4K…）→ 链接溢出 22 KB

**当时的权宜之计（错）**：把 g_old 搬到 DDR `0x08900000`。
实测代价：每帧 4000 读 + 4000 写 DDR ≈ **24 ms**（AXI 随机访问慢）→ CPU 35.5ms → 30fps。

## 六、下一步：方案 Z（硬件保存擦除历史）

**想法**：表项 word0（旧位置）本来就该由硬件维护，而不是 CPU 每帧写一遍。

| 改动 | 内容 |
|---|---|
| 表拆分 | `tab_hi[4096][31:0]`（新位置，CPU 写）+ `tab_lo[4096][31:0]`（旧位置，遍历器写回）；BRAM 总量不变（32 KB）|
| 遍历器 | 擦除用 tab_lo[idx]；绘制用 tab_hi[idx]；绘制完成 `tab_lo[idx] <= tab_hi[idx]` |
| gfx_regs | 每写 1 次 R_SPRTAB = 写 1 个表项（不再 2 字配对），`tab_wptr++` |
| 固件 | **每精灵只写 1 个 32 位字**（新位置）→ 写表时间减半（10.7→5.3 ms）；**删除 g_old 依赖**（省 32 KB RAM，可搬回片上） |

**预期**：CPU 35.5 → ~6 ms，fps 30 → ~55-60。
