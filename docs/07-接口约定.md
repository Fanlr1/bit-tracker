# 接口约定（核对官方模块后固化）

> 来源：逐个读官方 RTL 的端口声明（非推测）
> 日期：2026-10-05
> **用途：写任何新模块之前先查这里** —— 接口不匹配的返工代价远大于先看一眼
> ⚠️ 起因：M4 pixel_engine 初版按自己的习惯用了 `valid/ready`，核对后才发现官方视频链路用的是 `vs/de/hs` 同步

---

## 一、视频链路接口（关键：**不是 valid/ready**）

### 1.1 `frame_buffer` —— DDR ↔ 视频流桥

**文件**：`...\10_Ti60f225_sc431hai2hdmi_demo\Ti60f225_sc431hai2hdmi_v1\rtl\frame_buffer\frame_buffer.v`（350 行）

| 侧 | 端口 | 说明 |
|---|---|---|
| **视频写入侧** | `i_clk`, `i_vs`, `i_de`, `vin[I_VID_WIDTH-1:0]` | **场同步 + 数据有效**驱动，无握手 |
| **视频读出侧** | `o_clk`, `o_hs`, `o_vs`, `o_de`, `vout[O_VID_WIDTH-1:0]` | 标准视频时序 |
| **时序参数** | `H_FRONT_PORCH/H_SYNC/H_VALID/H_BACK_PORCH` + V 组，各 `[12:0]` | **外部传入**，勿依赖默认值 |
| **AXI** | 完整 AXI4 Master | ⚠️ 见 §二（带厂商扩展位）|

**参数**：`I_VID_WIDTH=16` / `O_VID_WIDTH=16` / `AXI_DATA_WIDTH=512` / `AXI_ADDR_WIDTH=33` / `BURST_LEN=15` / **`FB_NUM=3`**（三缓冲）/ `MAX_VID_WIDTH=1920` / `MAX_VID_HIGHT=1080`

> ⚠️ **两个已知坑**（来自 `docs/03`）：
> 1. `:105-112` 把 8 个时序寄存器初始化为 `13'd100`，注释写 `//( 50 )`，**与注释不符** → **必须显式传参**
> 2. `10` 号 demo 顶层把 `O_VID_WIDTH` 声明 16 却实接 **24 bit**（`{ch0_g,ch0_b}`）→ 靠 Verilog 宽松位宽蒙过去，**复用时必须自己统一**

### 1.2 `data_tx` —— 带 FIFO 的视频时序发生器

**文件**：同上目录 `data_tx.v`（437 行）

| 方向 | 端口 | 说明 |
|---|---|---|
| 上游 | `fifo_wr_data[VID_WIDTH-1:0]`, **`fifo_wr_en`** | **写使能驱动**，无 ready |
| 反压 | `fifo_wr_almost_full` | 上游必须看这个 |
| 帧同步 | **`fifo_rd_period`** | **每帧一个脉冲**（`frame_buffer.v` 用它把 DDR 读地址归零）|
| 配置 | `H_*` / `V_*` 各 `[12:0]` | 同 `frame_buffer` |
| 输出 | `vout`, `o_hs`, `o_vs`, `o_de` | 标准视频时序 |

**状态机**：`S_H_SYNC / S_H_BACK_PORCH / S_H_VALID / S_H_FRONT_PORCH` + V 组

### 1.3 `color_bar_rgb` v3.0 —— 纯时序发生器（**推荐复用**）

**文件**：`...\03_hdmi_tx_demo\hdmi_tx_demo_v2\rtl\color_bar_v3.0\color_bar_rgb.v`（361 行）

```verilog
module color_bar_rgb #(
    parameter DYN_EN=1'b0, HS_POLORY=1'b1, VS_POLORY=1'b1,
              SYMBOL_WIDTH='d10, SYMBOL_NUM='d3, PAR_PIXEL_NUM='d1,
              HFP=13'd100, HST=13'd100, HACT=13'd384, HBP=13'd100,
              VFP=13'd4,   VST=13'd5,   VACT=13'd288, VBP=13'd4,
              TEST_MODE=2'd0
)(
    input  wire clk, rst_n,
    input  wire [PAR_PIXEL_NUM*SYMBOL_NUM*SYMBOL_WIDTH-1:0] i_cfg_vid,   // 像素输入
    output reg  [15:0] h_cnt,      // ★ 当前像素 X 坐标（免费送）
    output reg  [15:0] v_cnt,      // ★ 当前像素 Y 坐标
    output reg         hs, vs, de,
    output reg [PAR_PIXEL_NUM*SYMBOL_NUM*SYMBOL_WIDTH-1:0] o_vid_data
);
```

- **`TEST_MODE=2'b11` = 像素透传**（`i_cfg_vid` → `o_vid_data`）← **我们要的**
- 实用配置：`SYMBOL_WIDTH=8, SYMBOL_NUM=3, PAR_PIXEL_NUM=1` → 数据宽 **24 bit（RGB888）**
- **`h_cnt`/`v_cnt` 可直接当 framebuffer 读地址 / BitBlt 目标坐标**
- ⚠️ **只有 v3.0 有 TEST_MODE**（`11` 号 demo 里的 v2.0 没有）
- ⚠️ `HFP_CNT = HFP/PAR_PIXEL_NUM`（`:73`）→ 多像素/时钟时参数会被**再除一次**

### 1.4 视频链路的数据流约定（总结）

```
[DDR] ──frame_buffer──> vout ──┐
                               │  de/vs 同步
         color_bar_rgb ────────>│  (i_cfg_vid 透传)
                               ▼
                          dvi_encoder ──> TMDS ──> HDMI
```

**⇒ 视频侧一律用 `de` + `vs`/`hs`，没有 `valid/ready`。**

## 二、AXI4 接口约定（⚠️ 有厂商扩展位）

### 2.1 `frame_buffer` 的 AXI4 Master 端口（`frame_buffer.v:44-87`）

**写地址通道**：
```
awid[5:0]  awaddr[32:0]  awlen[7:0]  awsize[2:0]  awburst[1:0]
awcache[3:0]  awprot[2:0]  awlock  awqos
awvalid  awready
⚠️ awcobuf   ⚠️ awapcmd   ⚠️ awallstrb     ← 【非标准 AXI4 信号】
```
**读地址通道**：`arid[5:0] araddr arlen arsize arburst arlock arvalid arready` + ⚠️ `arapcmd` `arqos` `arcache[3:0]` `arprot[2:0]`
**写数据**：`wdata[511:0] wstrb[63:0] wlast wvalid wready`
**读数据**：`rid[5:0] rdata[511:0] rlast rvalid rready rresp[1:0]`
**写响应**：`bid[5:0] bvalid bready`

> ⚠️ **`awcobuf` / `awapcmd` / `awallstrb` / `arapcmd` 不是标准 AXI4 信号** —— 套通用 AXI4 模板会漏掉。这几个是 Efinix DDR 控制器的扩展。

### 2.2 `axi4_slave`（SoC 侧从设备模板）

**文件**：`...\10_...\rtl\axi4_slave.v`（506 行）—— **端口与 `soc.v:487-526` 严格对齐**

```
axi_interrupt（输出）,
axi_aclk, axi_resetn,
AW: axi_awid[7:0] axi_awaddr[31:0] axi_awlen[7:0] axi_awsize[2:0] axi_awburst[1:0]
    axi_awlock axi_awcache[3:0] axi_awprot[2:0] axi_awqos[3:0] axi_awregion[3:0]
    axi_awvalid / axi_awready
W:  axi_wdata[31:0] axi_wstrb[3:0] axi_wlast axi_wvalid / axi_wready
B:  axi_bid[7:0] axi_bresp[1:0] axi_bvalid / axi_bready
AR: axi_arid[7:0] axi_araddr[31:0] ... axi_arvalid / axi_arready
R:  axi_rid[7:0] axi_rdata[31:0] axi_rresp[1:0] axi_rlast axi_rvalid / axi_rready
```
**状态机**：`IDLE / WR / WR_RESP / RD`
**⚠️ 无厂商扩展位**（这是标准 AXI4）—— 和 `frame_buffer` 那边**不一样**

## 三、⚠️ 纠错：`Ddr_Write.v` / `Ddr_Read.v` **不是 AXI Master 模板**

**实现计划 §四 原来把这两个标为「M5 DMA 的复用来源」，这是错的。**

**实测端口**（`08\...\rtl\common\Ddr_Write.v`，2722 行）：

| 端口组 | 信号 | 说明 |
|---|---|---|
| **5 个时钟域** | `Clk_TxCmd` / `Clk_TxDqs` / `Clk_TxDq` / `Clk_Core` / `Clk_Axi` | 各带独立复位 |
| **DDR 物理接口** | `O_Ddr_Cs_In` / `O_Ddr_Odt` / `O_Ddr_Dm_Hi` / `O_Ddr_Dm_Lo` | **直连 DDR 引脚** |
| **PHY 控制器接口** | `I_Phy_Cmd_Write` / `I_Phy_Cmd_Valid` / `I_Phy_Command` | 连 PHY |
| AXI 接口 | `I_AW_*` / `I_W_*` / `O_B_*` | 有，但**只是控制器内部的一环** |
| 测试/配置 | `I_T_*` / `Cfg_Wr_Latency` | 内部测试用 |

**⇒ 它是 DDR3 控制器【内部的写通道】，不能当独立的 AXI Master 复用。**

## 四、对我们模块设计的约束

| 模块 | 约束 |
|---|---|
| **M4 pixel_engine** | 已按 `valid/ready` 实现（**适合 DMA 流**）。**接视频侧时必须加适配层**：`de`/`vs` → `valid`，`valid` → `de` |
| **M5 DMA** | 抄 **`Demo\...\IMX219_HDMI_1080P\src\axi\axi4_ctrl.v`**（128 位、明文、带 tb）。<br>**不是** `Ddr_Write`（那是控制器内部模块，见 §三），**也不是** `axi4_m_gen`（实现加密，抄不了）|
| **M8 视频输出** | 用 `color_bar_rgb` v3.0（`TEST_MODE=11`）+ `dvi_encoder`，**de/vs 接口** |
| **M1 寄存器/AXI 从设备** | 抄 `axi4_slave.v`（标准 AXI4，无扩展位）|
| **像素格式** | 官方视频链路是 **16 bit（声明）/ 24 bit（实用）**；M4 现用 **32 bit（ARGB8888）** → **对接时需统一**，见下 |

### 4.1 像素格式决策（待定）

| 方案 | 优点 | 缺点 |
|---|---|---|
| **16 bit RGB565** | 直接兼容 `frame_buffer` 默认 | **无 A 通道** → Alpha 只能全局 |
| **24 bit RGB888** | 兼容 `color_bar_rgb` 实用配置 | 无 A 通道 |
| **32 bit ARGB8888**（M4 现用） | **有 A 通道 → 每像素 Alpha**；色彩无损 | 与官方 `frame_buffer` 默认不符，需自己写帧缓冲或改参数 |

**赛题原文只要求**：`输出像素 = 前景像素 * Alpha + 背景像素 * (1 - Alpha)` —— **没规定格式**，全局 Alpha 即可满足。

**⇒ 建议**：**M4 保持参数化 `DW`**，默认 32；**集成时按实际帧缓冲格式再定**。
