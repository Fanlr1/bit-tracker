## 二、900 精灵版（源码已提交，未部署）

- **实现**：`gfx_core` 分段 compact-source（128 像素/段）+ 表遍历单元（保留但未启用）
- **性能**：900×16×16 @ 59.2 fps（PROF cpu 13.5 ms，比黄金版 14.2 ms 还低）
- **文件**：`rtl/gfx/gfx_core.v`（已提交 5079067）、`work/backup/final-20261031/`（bitstream+hex）

### 为什么 DVI 不稳

- 时序 slack 全为正（pix_clk +1.164ns）
- framebuffer 正常、scanout 计数器增长
- **唯一变量**：RTL 改动导致 PnR 布局变化，把 DVI 串行器挤到远端
- **30 个 seed 都没有命中可用布局**

## 五、明天可走的路线（按性价比）

1. **分区约束**（30 分钟定位格式 + 20 分钟构建）：把 DVI 串行器钉死在芯片右上角 → 最有可能救回 900 精灵
