## 三、严重问题（逐条）

### ① `bitblt_axi_slave.v:445` — `reg_bpp` 只送 3 位，装不下 8 B/px

```verilog
L31   //   0x30 BPP          bytes per pixel (1/2/4/8), reset default 4 = ARGB8888
L343  reg [31:0] r_bpp;
L414  IDX_BPP: rdata_mux = r_bpp;          // 读回完整 32 位
L110  output wire [2:0] reg_bpp,           // ← 只有 3 位
L445  assign reg_bpp = r_bpp[2:0];
```
接收端同样装不下：
```verilog
bitblt_addr_gen.v:36   input wire [2:0] bytes_per_px,   // 1 / 2 / 4 / 8
```

**穷举验算**：`8 → 0`、`9 → 1`、`12 → 4`、`15 → 7`。

**后果**：纯静默截断，仿真上板均不报错。更坏的是**读回值（32 位）与生效值（低 3 位）不一致** —— 驱动写 8、读回 8，而引擎收到 0，软件自检也发现不了。

**注意**：整条链路（slave 端口 + addr_gen 端口）都是 3 位，**不是单点截断**。

### ② `bitblt_dma_wr.v:198-211` — B 通道握手未闭合

```verilog
S_RESP: begin
    m_axi_bready <= 1'b1;                 // 置 1
    if (m_axi_bvalid) begin               // ★ 本拍就可能成立
        m_axi_bready <= 1'b0;             // ★ 同一 always 块内后赋值覆盖前赋值
        if (m_axi_bresp != 2'b00) m_axi_b_error <= 1'b1;
        if (beats_left == 32'd0) state <= S_DONE; else state <= S_WAIT;
    end
end
```

**时序分析**：进入 `S_RESP` 那一拍，`m_axi_bready` 仍是 0（`S_WAIT` L169 清 0）；L199 的 `<= 1'b1` **要下一拍才生效**，而 L200 的 `if` **本拍就可能命中**。

**AXI 对 BVALID 没有最小延迟要求** —— 「收到最后一个 W 拍后寄存一拍 BVALID」是完全合规且常见的从设备实现。此时：
- L201 把 `bready` 拨回 0 ⇒ **BREADY 从未真正拉高**
- 该响应被 FSM 消费（状态已推进），但总线上握手未完成

**对照**：读引擎写对了 —— L146 用 `m_axi_arvalid && m_axi_arready`、L104 用 `rvalid & rready`，都是真握手条件。

**后果链**：B 握手在总线上永不闭合 → 陈旧响应被下一个 burst 消费 → 响应与 burst 永久错位一拍 → 最后一个 burst 可能拿前一个响应就宣告 `S_DONE` ⇒ **`m_axi_b_error` 漏检** → 早熟的 `done` 经 `bitblt_top.v:457-463` 的 `all_done → line_ack` 让 addr_gen 提前推进 ⇒ 整帧错位放大。

**为什么 tb 没抓到**：tb 的 slave 两段式，`BVALID` 在进入 `SL_RESP` 的**下一拍**才拉高（`tb_bitblt_dma_wr.v:169-178`），恰好提供 1 拍 B 延迟使 `bready` 同拍有效 —— **合作型 slave 掩盖了缺陷**。

### ③ `bitblt_dma_wr.v:101 / 171 / 187` — AWADDR 在 AWVALID 有效期间会变化

```verilog
L101  assign m_axi_awaddr = cur_addr;          // 组合输出
L171  S_WAIT:  m_axi_awvalid <= 1'b1;          // AW 拉高，同时 state <= S_DATA
L187  S_DATA:  if (w_fire) cur_addr <= cur_addr + BYTES_PER_BEAT;   // ★ 自增
L141  if (m_axi_awvalid && m_axi_awready) m_axi_awvalid <= 1'b0;    // AW 握手后才清
```

**AXI4 要求 AW 载荷从 AWVALID 拉高到 AWREADY 之间保持不变**，且**明确允许 W 先于 AW 被接受**（两通道独立）。

**⇒ 只要 AWREADY 晚于第一个被接受的 W 拍**（写地址通道有反压：FIFO 满 / 仲裁让位），`cur_addr` 就在 AWVALID 仍为高时自增 ⇒ **AW 载荷在 valid 期间不稳定**。

**后果**：slave 可能把 burst 起始地址采成 `base + 16N` ⇒ **整条 burst 写到错误地址**（显存数据损坏，而状态位显示成功）。`awlen` 不受影响（`burst_len_m1` 只在 `S_WAIT` 写）。

**为什么 tb 没抓到**：tb 的 slave 在 `awvalid && wvalid` 时**同拍**拉高 `awready` 与 `wready`（`tb_bitblt_dma_wr.v:145-147`），两者永远同时有效 ⇒ AW 恰与第一个 W 拍同拍握手，`cur_addr` 尚未来得及变。

### ④ `bitblt_video_out.v:293` — `m_axi_arlen` 8 位截断，且与行像素数强耦合

```verilog
L293  assign m_axi_arlen = (fb_width >> 2) - 16'd1;    // 目标是 8 位
L261  if (px_in_line == fb_width - 16'd1) begin ... rd_row <= ...; end
```

一个突发取回 `P_b = 4·((((fb_width>>2)-1) & 8'hFF) + 1)` 个像素，而 `rd_row` 自增条件是「推满 `fb_width` 个像素」—— **只有 `fb_width % P_b == 0` 才自洽**。

| fb_width | (>>2)−1 | arlen(8bit) | P_b | fb_width % P_b | 结果 |
|---|---|---|---|---|---|
| **640（当前）** | 159 | 159 | 640 | 0 | ✅ 一突发 = 一行 |
| 800 | 199 | 199 | 800 | 0 | ✅ |
| 1024 | 255 | 255 | 1024 | 0 | ✅ |
| 1025 | 256 | **255** | 1024 | **1** | ❌ 第 5 突发首拍即 wrap，其后 1023 像素地址属旧行 |
| 1280 | 319 | **63** | 256 | 0 | ⚠️ 侥幸（1280 = 5×256），无断言保护 |
| 1366 | 341 | **84** | 340 | **6** | ❌ 第 5 突发中途 wrap |
| 1920 | 479 | **223** | 896 | **128** | ❌ 重复 128+768 像素 → 撕裂 |
| 1..3 | 0−1 = 0xFFFF | 255 | 1024 | ≠0 | ❌ 一个突发内 `px_in_line` 环绕多次，`rd_row` 飞掉 |

**后果**：除「4 的倍数且 ≤1024」外，扫描输出要么卡在第 0 行、要么行/地址错位；**无断言、无错误标志**，现象只是「画面静止/错行」。

**⚠️ 当前用的 640 是安全的，但这是「恰好安全」而非「保证安全」。**

### ⑤ `alpha_blend.v:57-58` + `tb_alpha_blend.v:59-64` — `>>8` 代替 `/255`，而 TB 把错误值当金标准

```verilog
// alpha_blend.v
assign out = dsp_p[15:8];        // dsp_p = fg*a + bg*(255-a) = x，取 ⌊x/256⌋ 而非 ⌊x/255⌋
```
注释 L2 自认 `approximated by >>8 for now`。

**数学上可确定**：`fg × 255 = fg × 256 − fg` ⇒ **`out = fg − 1`（fg ≥ 1）**，恒有 `⌊x/256⌋ ≤ ⌊x/255⌋` ⇒ **误差永不为正，是系统性偏暗**。

**穷举验算**（x 遍历 8 位输入可达的全部中间值）：

| fg | bg | alpha | x | >>8 输出 | 正确 ⌊x/255⌋ | 差 |
|---|---|---|---|---|---|---|
| 255 | 0 | 255 | 65025 | **254** | 255 | −1 |
| 200 | 10 | 255 | 51000 | **199** | 200 | −1（正是 TB 用例）|
| 128 | 0 | 255 | 32640 | **127** | 128 | −1 |
| 1 | 0 | 255 | 255 | **0** | 1 | −1 |
| 0 | 0 | 255 | 0 | 0 | 0 | 0 |
| 100 | 0 | 128 | 12800 | 50 | 50 | 0 |

- `alpha=255`：256 个 fg 取值中 **255 个偏暗 1 LSB**
- `alpha=0`（全背景）：同样 255/256 偏暗
- 全域 `x∈[0,65025]`：**49.8% 取值不一致，最大误差 1，平均误差 +0.498（恒偏暗）**
- 极端相对误差：`alpha=1, fg=1 → x=1 → out=0`（应 1，−100%）

**而 TB 的期望值是从实现倒推的**：

```verilog
// tb_alpha_blend.v
L59: // alpha = 255 -> pure foreground: (200*255 + 10*0) >> 8 = 199
L60: do_check(8'd200, 8'd10, 8'd255, 8'd199, "full-fg");   ← 规格值应为 200
L61: // alpha = 0   -> pure background: (200*0 + 10*255) >> 8 = 9
L62: do_check(8'd200, 8'd10, 8'd0,   8'd9,   "full-bg");   ← 规格值应为 10
```

**注释写着 "pure foreground"（纯前景），断言的却是 199** —— 而纯前景按定义必须等于 `fg = 200`。

**⇒ 这条比「不检查」更危险**：TB 确实在跑、确实在比较、确实报 PASS，**但比较的基准本身就是 bug**。

**⚠️ 但它是孤儿模块（当前无害）**：

```
src\ 下例化 alpha_blend ：★ 无任何例化
bitblt_top.v L375      ：例化的是 bitblt_pixel_engine
syn\src 里有没有它      ：False
唯一例化处             ：tb\tb_alpha_blend.v（它自己的 TB）
```

⇒ 既不参与综合也不参与顶层仿真。**bug 当前不影响功能**，但那个 TB 的「全 PASS」会让人误以为 DSP48 混合路径已验证。

**对照：`pixel_engine` 用的是精确公式**（穷举验证 `x∈[0,65025]` **失配 0 处**）：

```verilog
bitblt_pixel_engine.v L90-93
wire [17:0] rounded = sum + 18'd1 + {10'd0, sum[17:8]};
```
⇒ **同一个工程里两套混合公式，结果差 1 LSB。**

### 7.1 脉冲被当状态位（跨 3 个文件）

## 十、方法与局限

**方法**：
- 12 个 RTL + 11 个 TB **逐行阅读**（非抽样）
- 算术问题**穷举验算**：`x` 遍历 `[0,65025]`（8 位输入可达的全部中间值）与 `[0,130050]`（注释声称范围），逐点比对 `⌊x/255⌋`、`x>>8`、`(x+1+(x>>8))>>8`、`(…)&0xFF`
- 交叉核对集成上下文（`bitblt_top.v` / `pixel_engine.v` / tb 的 slave 模型）以**排除误报**
- 关键结论**独立复核**（本次报告中的 7 个严重项均已复核）

**关键数字**：
```
engine 恒等式 [0,65025] 失配 0        [0,130050] 失配 254
rounded[15:8] 截断自 x=65280 起错，累计 64771 处
>>8 对 [0,65025] 失配 32386 (49.8%)，max 1，mean +0.498；alpha=255 时 255/256 偏暗
```

**局限**：
1. `EFX_DSP48` 是厂商原语，树内无源码/仿真模型 —— 其 `RST` 极性、P 复位行为、`SHIFT_ENA=0` 的确切语义**无法核实**
2. **未审功能正确性** —— 标 ⚠️ 的条目（第八节）需要功能验证方定论
3. 未涉及厂商 IP（`dual_clock_fifo.v` / `simple_dual_port_ram.v` 是 Efinix 官方）、第三方 IP（`Axi_Mux.v`）、生成的网表
