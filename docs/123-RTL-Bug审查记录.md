# 123 · GFX 引擎 RTL Bug 审查记录（2026-11-01）

> 审查范围：`gfx_core.v` / `gfx_mem.v` / `gfx_scanout.v` / `gfx_regs.v`（compact 版）
> 方法：人工逐段审查 + 静态数组边界扫描脚本

## Bug 1（已修）：`spx`/`bpx` 越界写

**位置**：`gfx_core.v` L176-184

**问题**：
- 段 0 的 burst 长度 = `(spx_off + 128 + 7) >> 3`，`spx_off` 最大 7 → 最多 **17 beats**
- 写逻辑 `spx[{beatidx,3'b000} + ku]` 在 beatidx=16 时写 **spx[128..135]**
- `spx` 只有 `[0:127]` → **越界写** → 综合后覆盖相邻存储（bpx/opx）

**症状**：精灵形状异常（边缘错乱）

**修复**：写使能加 `beatidx < 16` 守卫（多余拍只接收不写）

**状态**：✅ 已修（用户确认形状恢复正常）

## Bug 2（不需要修）：`spx`/`bpx` 读越界

**位置**：`gfx_core.v` L236-237

**问题**：
- 读地址 `spx[p[6:0] + soff + spx_base]`
- `soff > 0`（源非 16B 对齐）时：112 + 15 + 7 = 134 > 127 → 越界读

**验证**：固件所有精灵源都 16B 对齐（`SPR_BASE=0x08870000`, `SPR_BYTES=512`, `+5*512`）→ **`soff` 恒为 0** → 不触发

**结论**：不需要修（尝试修复时加的比较器导致资源超容量 61733>60800，已回退）

## Bug 3（未修，疑似黑屏相关）：`bank_*` 跨时钟域无同步

**位置**：`gfx_scanout.v`
- 写域：`clk`（L261-267，引擎/axi 域）
- 读域：`pclk`（L129-192，像素域，直接读 `bank_ok/bank_row/bank_epoch`）
- **无 2 级同步器** → 亚稳态可能

**为什么黄金版稳定**：黄金版引擎读少 → bank 更新频率低 → 冲突概率低
**为什么 compact 黑**：分段读使 bank 更新频繁 → 冲突概率上升

**修复成本**：16 项 × (1+11+16) bit × 2 级 ≈ 900 FF，可能影响布局（需重新抽签）

**状态**：⏸ 未修（待验证 Bug 1 修复 + 完美校准 seed 后，若仍黑再修）

## 审查中发现的其他要点

| 项 | 结论 |
|---|---|
| `gfx_mem` 的 `wf_data/wf_strb`（16 项）| 索引都带 `[3:0]` 截断，安全 |
