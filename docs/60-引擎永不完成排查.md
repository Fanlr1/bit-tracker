# 60 - 板上调试续：从「第二行 printf 就死」到「引擎永不完成」（2026-10-13 下半场）

> **接 docs/59。本文件记录 59 之后的突破与剩余问题。**
> **一句话**：修好两个真根因（mcycle CSR、%02u 格式符）后，应用从「第二行 printf 就崩」
> 推进到「跑完软件填充」；随后定位到**引擎在 hardware fill 阶段永不完成**（BUSY 恒 1，且 DDR 被写错）。

## 一、两个真根因（都已修复并板上验证）

| # | 根因 | 症状 | 修复 |
|---|---|---|---|
| 1 | **REDUCED_CSR=1'b1 摘掉了 mcycle（CSR 0xB00）的译码** | mcause=2 非法指令，mepc 指向 csrr a5,mcycle | 在 ip/soc/soc.v 补回译码 + 读数据通路 |
| 2 | **%02u 格式符**（上次 %u→%d 替换未覆盖）| mcause=5 Load fault，读地址 5 | 全部 %<数字>u → %d（并修回被正则误伤的取模）|

**教训 A**：bsp_printf（print.h）只支持 c/s/d/X/x；**不认识的格式符会让内层 while 继续扫描**，
一路吃到字符串末尾 ⇒ 越界读 ⇒ Load fault。

**教训 B**：正则替换 C 源码要限定在**字符串字面量**内，否则会把取模运算 a % 100u 误改成 % 100d。

## 二、诊断手段（本轮最有价值的资产）

| 手段 | 用法 | 为什么关键 |
|---|---|---|
| **RAM 探针** | 应用里 PROBE(n) 写 0xF9000F00+4n | **BRAM 不经 AXI**，总线挂了也能被 openocd mdw 读到 |
| **提前装 trap** | 把 intr_init() 提到 main() 开头 | 异常不再静默，trap() 打印 mcause/mepc —— 找到两个根因的直接原因 |
| **汇编探针注入** | load_image + reset/resume | 不烧 flash、不重综合，2 分钟一轮 |
| **空闲应用** | flash 放纯 while(1) 应用 | 真应用一跑就把调试器挡在外面 |

## 四、当前唯一确凿症状

```
marker[1] = 1           STATUS 的 busy 位，等 0.24 s 后仍为 1
marker[2] = 1           再读一次仍是 1  ⇒ AXI 活着（不是总线死）
0x08000000 = 02e12023   ⇒ 写入错数据（既非 FILL_COLOR 也非上次的值）
```

**⇒ 引擎启动了、DDR 被动过、但永不完成。** 卡点在 bitblt_top.v 的行完成握手：

```verilog
wire all_done = (compact_src | f_src | rd_src_done) &
                (f_dst | rd_dst_done) &
                (f_wr  | wr_done);
assign line_ack = all_done & ~ack_sent;   // 三个 DMA 全 done 才推进一行
```

## 五、下一步（明确的单点）

**把引擎内部状态引到可观测处**（下一轮唯一该做的事）：

| 信号 | 位置 |
|---|---|
| f_src / f_dst / f_wr / all_done / ack_sent | bitblt_top.v L804-828 |
| rd_src_busy / rd_dst_busy / wr_busy | bitblt_top.v L241 / L750 |
| px_in_valid / px_in_ready / px_valid / px_ready | bitblt_top.v L695 / L764 |

**优先怀疑**（同类问题的历史记录见 bitblt_top.v L708-713）：

```verilog
assign rd_src_ready = spr_fetch_active | (px_in_ready & rd_dst_valid);
assign rd_dst_ready = px_in_ready & rd_src_valid;
```

这是**互相依赖**的互锁：任一 reader 的数据不来，另一个也停。而 FILL 模式下 rd_src 仍被无条件启动
（src_start = line_start & (~compact_src | line_index==0)，L601），它读的是 src_base（复位默认 0），
而 all_done 又要求 (compact_src | f_src | rd_src_done) —— **若源引擎在「无人消费其数据」时不能自行完成，就是死锁点**。

**观测方式**：把上述信号接到 dbg_observ 之类的**不经 AXI 的出口**（GPIO/APB 域）。

## 七、工程坑（今天新增）

| 坑 | 真相 |
|---|---|
| 改了 soc.v 不生效 | **必须 clean build**（移开 work_syn_sys / work_pnr_sys / outflow）|
| 删 soc.v 想强制重生成 IP | **map 直接失败**——IP 生成是独立步骤，不在 efx_run 里 |
| openocd 残留进程 | 超时后进程不退，占住 JTAG ⇒ 后续全部 mpsse_flush 超时；先 Stop-Process |
| 同时跑串口脚本 + openocd | FTDI 通道冲突，表现为 Can't communicate with the CPU ⇒ **误判成总线死了** |
| 单拍探针测不出 burst 问题 | 引擎 DMA 是 burst；探针要用真实多拍写才有判别力 |
