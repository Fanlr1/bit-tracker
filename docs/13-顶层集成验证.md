**打通的链路**：
```
SoC 写寄存器 → M3 生成行地址 → 两个读引擎 DDR 突发读 → M4 四像素并行处理
    → 写引擎带 strobe 突发写回 → 三引擎合流 line_ack → 推进下一行
```

**TB 组成**（`tb/tb_bitblt_top.v`）：
- 一个 AXI4 master BFM（充当 SoC 写寄存器）
- 两个 `axi_rd_slave`（充当 DDR 读端，返回可预测的地址+拍号模式）
- 一个 `axi_wr_slave`（充当 DDR 写端，锁存地址/数据/strobe）

## 二、★ 端到端挖出的 5 个 bug（单模块测试全部漏掉）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| **1** | 地址高位为 `x` | `localparam [AXI_DW/8-1:0] BYTES_PER_BEAT` 只有 16 位，却读 `[AXI_AW-1:0]`（32 位）→ 越界位被填 `x`，**地址增量高 16 位不定** | 声明成 `[AXI_AW-1:0]`。**由 `iverilog -Wall` 的 elaboration 警告发现，TB 完全测不到**（TB 不检查地址） |
| **2** | 读引擎吞数据、流水线挂死 | `dout_valid` 在**同一拍**既被 `r_fire` 置 1、又被消费清 0，**后赋值覆盖前赋值** | `m_axi_rready` 改**组合**（`!dout_valid \| dout_ready`），清 valid 时加 `else if`（无新数据才清） |
| **3** | 写引擎用同一份数据连写 2 拍 | `m_axi_wvalid` **未用 `din_valid` 限定** → 像素流水线停顿时仍用 `din` 上的旧值发拍 | `wvalid = wvalid_r & din_valid`（FSM 意图 **与** 数据有效） |
| **4** | **只跑第一行**，之后死锁 | M3 在 `line_ack` 同拍 `line_req <= 0` 又 `<= 1`，**后者覆盖** → `line_req` 永不下降 → 下游边沿检测再无上升沿 | 新增 `S_GAP` 状态：`line_req` **低一拍**再拉高 |
| **5** | 写引擎永久等数据 | 读引擎 `S_DONE` **无条件清 `dout_valid`**，把刚推进输出寄存器的最后一拍丢掉；两个读引擎的末拍不同步时必丢 | `S_DONE` 里等 `!(dout_valid && !dout_ready)` 才完成 |

### 另修正 2 个 TB 自身的 bug（非设计问题）

| # | 现象 | 根因 |
|---|---|---|
| **6** | `rlast` 在第 0 拍就拉高 | TB slave 用"预测下一拍"的**寄存器**写法，长突发碰巧对，**2 拍突发必错**。正解：`rlast` 必须是**组合**（`cnt == len_r`） |
| **7** | 两拍 R 数据完全相同 | 同一类错位：`rdata` 也寄存，**比 beat 计数器晚一拍**。正解：`rdata` 同样**组合**跟随 `cnt` |

## 三、为什么单模块测试一个都没抓到

| Bug | 单模块 TB 为何漏掉 |
|---|---|
| 1 地址变 `x` | TB 的 slave 模型**从不检查地址**，只数拍数 |
| 2 / 3 握手覆盖 | 单模块 TB 的下游**永远 ready**，从不产生反压 → 覆盖分支走不到 |
| 4 只跑一行 | M3 的 TB **直接驱动 `line_ack` 脉冲**，不经过 `pulse_gen` → 掩盖了边沿问题 |
| 5 末拍丢失 | 单模块 TB 的下游**立刻消费**，不存在"末拍窗口错过" |

**⇒ 结论：反压、跨模块握手、边沿检测这三类问题，只有端到端仿真能暴露。**
**它们也正好是上板后最难查的一类问题（表现为"卡死"而非"数据错"）。**

## 四、⚠️ 已知简化（第一版有意为之，未验证）

| # | 简化 | 影响 | 何时处理 |
|---|---|---|---|
| 1 | **所有模式都启动两个读引擎**（FILL 也读、数据丢弃）| DDR 访问从 3 次/像素行变 4 次，**占用率 13.8% → 18.4%** | 带宽成瓶颈时 |
| 2 | **`in_valid = rd_src_valid & rd_dst_valid`**（取 AND）| 慢的一方拖住快的一方；两个读引擎访问同一 DDR，延迟接近，实测无碍 | 出现吞吐问题时改用双 FIFO 解耦 |
| 3 | **不支持每像素 Alpha**（`key_use_pixel_a = 0`）| 只做全局 Alpha，赛题原文即可满足 | 可作为加分项后补 |
| 4 | **写引擎无读通道** | `Axi_Mux` 的 S3 端口 AW/W/B 之外的 AR/R **需在 system_top 接常量** | 集成时 |

## 五、复现方法

```powershell
cd C:\fpga_work\syn   # 或工作区 work\bitblt_sim
iverilog -g2005 -o tb_top.out `
  rtl\bitblt_top.v rtl\bitblt_axi_slave.v rtl\bitblt_addr_gen.v `
  rtl\bitblt_pixel_engine.v rtl\bitblt_dma_rd.v rtl\bitblt_dma_wr.v `
  rtl\bitblt_pulse_gen.v tb\tb_bitblt_top.v
vvp tb_top.out
```

**调试建议**：TB 内置了诊断打印（`line_start` / `line_ack` / 各引擎 `done` / AR 地址与 arlen / R 数据与 rlast）。
出问题时**先看这张时序表**，比翻波形快得多 —— 上面 5 个 bug 全部靠它定位。

## 六、双仿真器交叉验证

```
iVerilog : PASS: all checks OK
Questa   : Errors: 0, Warnings: 0     逐条一致
```

**Questa 额外抓到一个 iVerilog 容忍的问题**：
TB 的诊断块引用了**在文件后面才声明**的 `rd0_arvalid` 等 wire。
**iVerilog 隐式建 wire 放行，Questa 直接报 8 个错**（`Undefined variable` + `already declared`）。
⇒ 把诊断块移到声明之后即可。**这是双仿真器策略的直接收益**。
