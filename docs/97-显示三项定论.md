# 94 - 显示问题的三项定论（2026-10-24 夜）

> 接 [docs/93](93-首屏调试与双缓冲地址问题.md)（精灵画进去但看不见）
> 本文记录 goal 三轮内的实测结论，均有板上证据。

## 一、RGB565 通道顺序：**没有交换**（假设排除）

`main.c:161`：

    #define ARGB_TO_565(c) \
        ((uint16_t)((((c) >> 8) & 0xF800u) | (((c) >> 5) & 0x07E0u) | (((c) >> 3) & 0x001Fu)))

对 `COL_BG = ARGB(0xFF, 0x10, 0x10, 0x20)` 手算：

| 项 | 计算 | 结果 |
|---|---|---|
| R | `(0xFF101020 >> 8) & 0xF800` | `0x1000` |
| G | `(0xFF101020 >> 5) & 0x07E0` | `0x0800` |
| B | `(0xFF101020 >> 3) & 0x001F` | `0x0004` |
| **合计** | | **`0x1804`** |

⇒ **R=0x10 G=0x10 B=0x04，本身就是偏红紫的暗色**。屏幕上看到的"暗红"与代码一致，**不是 R/B 交换**。

## 二、白色点线 = `LOCATOR BAR`（有意绘制，非缺陷）

`main.c:1563-1570`：

    // 2026-10-24: LOCATOR BAR. An 8-pixel white bar across the very top
    // of buf[0], painted EVERY frame (the per-frame clear would erase a one-off).
    blt_fill(FB_BASE, FB_W, 8u, FB_STRIDE, 0xFFFFu);

**用途**：验证扫描输出是否读对了 base 与行映射。

### 它为什么会在画面中部

`bitblt_video_out.v:587-591` 的注释记录了实测：

    a locator bar painted at framebuffer y=0..7 was first seen along the top edge
    and later about half way down the panel, and the whole picture appeared to
    flicker as the offset kept moving

⇒ **`rd_row` 与屏幕行永久错位且累积**（starvation 时 `rd_row` 只按写入 beat 推进，不看扫描位置）。

## 三、★ `rd_row` 归零修复（10-24 realign 版）**有害，不可用**

`bitblt_video_out.v:620-622` 加了每帧垂直消隐归零：

    end else if (vb_s2) begin
        px_in_line <= 16'd0;
        rd_row     <= 16'd0;
    end

**板上实测（2026-10-24 22:20 重配置 realign 版，md5 `6d513fb4…`）**：

    mismatching pixels : 959128          ← 95 万个像素错误
    [TEST:FAIL] copy-readback-1000x

**对照 01:00 版（md5 `39b89162…`）**：

    mismatching pixels : 0
    [TEST:PASS] copy-readback-1000x

⇒ **realign 版的归零引入了数据损坏**（很可能与 FIFO 读侧并发冲突，归零只清计数器不清数据管道）。
**结论：realign 版不可用于演示，当前应使用 01:00 版。**

## 四、`game-sustained-density` FAIL = 慢态的另一种表现

`main.c:827`：

    test_result("game-sustained-density", peak_live >= 200u,
                "the walker did not sustain a dense screen");

代码注释（823-826）直接写了失败机制：

    a slow or stalling walker retires sprites late, so live count drops

⇒ 与 [docs/92](92-慢态尝试与未确证.md) 的 `walker 卡 S_RUN` 是**同一根因**，不是独立的显示问题。

## 六、下一步

1. **LOCATOR BAR 漂移**：若要修，需在归零的同时**清 FIFO 数据管道**（realign 版只清了计数器）；
2. **`game-sustained-density`**：即慢态，需回到 docs/92 的两处缺陷继续查；
