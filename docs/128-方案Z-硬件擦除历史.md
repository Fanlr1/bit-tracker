## 一、硬件改动（完整）

| 项 | 127 版 | 方案 Z |
|---|---|---|
| 表 RAM | 4096×64（word0 旧位置、word1 新位置，**都由 CPU 写**）| `tab_hi` 4096×32（新位置，CPU 写）<br>`tab_lo0`/`tab_lo1` 4096×32 ×2（旧位置，遍历器写回，**按 framebuffer 分 bank**）|
| RAM 块 | 32 | 48（+16）|
| CPU 写表 | 2 字/精灵（8000 次）| **1 字/精灵（4000 次）** |
| 擦除历史 | 固件 g_old 数组（32 KB，曾挤到 DDR）| **硬件表项**（固件省 28 KB RAM）|
| 寄存器 | — | `R_SPRALPHA=0xA8`（alpha+ck 的全局 alpha）|

遍历器：phase0 擦 `tab_lo{cur_buf}[idx]` → phase1 绘 `tab_hi[idx]`（OP_BLIT, alpha+ck）→ 写回 `tab_lo{cur_buf}[idx]`。

| # | 现象 | 根因 | 修复 |

## 四、性能分析（下一轮的起点）

- 引擎执行 **8000 条 8×8 命令 ≈ 22.7 ms**（2.84 µs/命令）
- 每精灵：擦 FILL 8 行写（8 事务）+ 绘 BLIT 8 行×(读背景+写)（16 事务）= 24 事务
- 4000 精灵 = 96000 DDR 事务/帧 → 每事务 ≈ 283 ns（28 周期 @100 MHz）
- 要 60 fps（16.7 ms/帧）需每事务 ≤ 17.5 周期，或减少事务数

**候选优化（按性价比）**：
1. **CPU 不等遍历器（流水化）**：本帧写表后立即返回，下一帧再等 → 帧时间 = max(CPU 5.3, 引擎 22.7) ≈ 22.7 ms → **44 fps**
2. **扫 PnR seed**：`work/_seedfix.py`，可能 +10~20%
3. **混合绘制模式**：不透明精灵走 `COPY_KEY`（8 事务，不读背景），半透明精灵走 `BLIT`（16 事务）→ 若 3/4 不透明，事务数 96000→64000 → **~55 fps**
4. 降精灵数：3200 → ~45 fps（但要求是 4000）
