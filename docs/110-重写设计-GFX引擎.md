# 110 - 重写设计：GFX 图形加速引擎（v2）

> 目的：用一套**干净、可验证、不会锁死总线**的图形子系统替换旧的 `bitblt_*` 那一套。
> 参考：FrameSpeed-Engine（同赛题公开源码）的 `fs_scanout` / `fs_read_arbiter` / `fs_blitter` / `fs_alpha565`。
> 约束：厂商加密 IP（`ddr3_controller/`、`ip/soc/soc.v`、`dvi_encoder/encode`）不动。

---

## 一、必须解决的四个旧问题（重写的第一性依据）

| # | 旧问题 | 旧原因 | 新对策（设计上的铁律） |
|---|---|---|---|
| 1 | **总线锁死 / 慢态**（读延迟 58,000 拍，CPU 挂死） | Axi_Mux 的 R 通道"等 rlast 才换通道"，任一从设备 `rready=0` 就锁死整条 R 总线 | **单一 GFX 主设备**；GFX 的 `rready` **恒为 1**；一次只维持**一个在途突发** |
| 2 | **画面撕裂**（上半屏旧帧/下半屏新帧） | 翻页只写 `FB_BASE`，FIFO 里还压着旧帧像素；无帧序号 | **双行 bank + epoch**：行必须 `bank_epoch == 当前帧 epoch` 才显示 |
| 3 | **抖动 / 半行黑** | 每像素判 `~fifo_empty`，行内 de 会翻转 | **行首锁存 `row_ok`，整行统一**；欠载整行黑 |
| 4 | **不可观测**（只能肉眼看屏） | 没有欠载/错误计数 | `underruns / shown / axi_errors / scan_frames / scan_lines` 全部可读 |

## 二、顶层结构（重写后）

```
system_top
 ├─ ddr3_top                 厂商，保留
 ├─ soc                       厂商，保留（axiA = 寄存器窗口 0xE1000000）
 ├─ Axi_Mux                   保留，只接 2 个从端口
 │     S0 = SoC DDR master
 │     S1 = GFX 唯一主端口（读 + 写）
 ├─ gfx_top                   新引擎（本次重写）
 │     ├─ gfx_regs            AXI4-Lite 从设备 + 寄存器 + 命令 FIFO
 │     ├─ gfx_core            矩形引擎（fill/copy/blend/key + 裁剪 + OOB）
 │     ├─ gfx_scanout         双行 bank + epoch + commit/accept
 │     └─ gfx_mem             读仲裁 + 写通道 + AXI4 master
 └─ dvi_encoder               厂商，保留
```

**关键变化**：旧设计的 4 个 AXI 主设备（源读/背景读/写/扫描）合并为 **1 个**。
Axi_Mux 的 R 通道从此只有 CPU 与 GFX 两个竞争者，且 GFX 永不停顿。

## 三、内存接口三条铁律（消除死锁）

### 3.1 读
- **一次只允许一个突发在途**（FrameSpeed `fs_read_arbiter` 的做法）。
- 客户端提交请求时必须保证"一旦被接受，16 beats 一定收得下"。
- `m_axi_rready = 1`（除复位外恒为 1）—— **AXI 从设备永远不会看到 GFX 拒收数据**。
- 突发长度 ≤ 16 beats（256 B），且**不跨 4 KB**（行 stride 4 KB 对齐，天然满足）。

### 3.2 写
- 一次一个写在途（AW/W/B 走完再发下一个）。
- 写数据来自内部 FIFO，`wvalid` 一旦拉高不撤销。

### 3.3 仲裁
- 读客户端优先级：**scanout > blit 源 > blit 背景 > 描述符**。
- 只在**突发边界**切换，绝不抢占已接受的突发。

## 四、显示扫描（gfx_scanout）

### 4.1 结构
```
pclk 域                                    clk 域（100 MHz）
--------                                   ----------------
h/v 计数 ── 行号 y ── mailbox(req/ack) ──> 行 FSM：15 × 256B 突发
   │                                            │
   │ 行首锁存 row_ok                            v
   │ (bank_ok && bank_row==y                  双 bank BRAM
   │  && bank_epoch==epoch)                  (960 × 32b × 2)
   v                                            │
RGB565 输出 <── 1 像素/pclk <── 32b 读（2 px/word）
```

### 4.2 行完整性规则（FrameSpeed `fs_scanout` 原文语义）
- 行首（x==0）锁存 `row_ok = ready_row`；**整行用这一个值**。
- 欠载 → 整行输出黑（`rgb=0`），`underruns++`。
- 行到达时 `bank_epoch != epoch` → 视为未就绪 → 整行黑。

### 4.3 双缓冲提交（commit / accept）
- 软件写 `FB_NEXT` + `FB_SEQ`，再写 `FB_COMMIT=1`。
- 硬件在**帧首**（v 计数回绕时）接受：`front <= next`，`accepted_seq <= seq`，`epoch++`。
- `FB_ACCEPTED` 可读，软件据此确认翻页完成。

### 4.4 行预算
- 1920 px × 2 B = 3840 B = 15 × 256 B 突发 = 240 beats。
- 一行 2200 pclk = 14.8 µs；100 MHz 下 1481 拍。**读占用 16%**。

### 5.1 操作码

| 码 | 名称 | 源 | 背景 | 说明 |
|---|---|---|---|---|
| 0 | FILL | 无 | 无 | 纯色填充 |
| 1 | COPY | 有 | 无 | 矩形拷贝 |
| 2 | BLEND | 有 | 有 | `fg*a + bg*(1-a)` |
| 3 | KEY | 有 | 有 | 源像素 == KEY 时保留背景 |
| 4 | BLIT | 有 | 有 | BLEND + KEY（精灵标准路径）|
| 5 | COPY_KEY | 有 | 有 | COPY + KEY |

### 5.2 命令 FIFO
- 深度 16，每条 128 位（快照 12 个参数）。
- 写 `CTRL.START` 时压入；FIFO 满则忽略并置 `STATUS[4]`。
- 硬件依次执行，完成一条 `DONE_CNT++`，并在中断使能时给中断。

## 六、像素通路（gfx_core）

- **8 px / clk**（AXI 128 位 = 8 × RGB565）。
- 行内按 16 B 对齐切分：
  - 源读地址 = align16(src + y*ss + x0*2)，像素偏移 `soff = ((src+y*ss+x0*2) & 15) >> 1`
  - 目的写地址 = align16(dst + y*ds + x0*2)，`doff` 同理
  - 首尾 beat 用 `wstrb` 精确屏蔽（AXI 允许，且不读改写）
- 混合：`out = (fg*a + bg*(255-a) + 128) / 255`，用 `(v + (v>>8)) >> 8` 近似。
- 键控：逐像素比较，命中则输出背景（或保持）。
- 裁剪：`[x0,x1) × [y0,y1)`，与操作矩形求交；空交集置 CLIPPED，不算错误。
- OOB：目的地址必须落在 `[FB_POOL_LO, FB_POOL_HI)`，否则拒写并记录 `ERR_ADDR`。

## 九、与旧设计的取舍说明

| 项 | 旧 | 新 | 理由 |
|---|---|---|---|
| AXI 主设备 | 4 | 1 | 锁死源于多主 + R 通道串行 |
| 扫描行缓冲 | FWFT FIFO 4096 px | 双行 bank 960 words × 2 | 行完整性 + epoch |
| 翻页 | 写 FB_BASE | commit/accept + epoch | 消除撕裂 |
| 命令 | 每条等完成 | 16 深 FIFO 异步执行 | 去掉 CPU 轮询 |
| 精灵 | 硬件 8192 槽 walker | v2.0 软件下发 + FIFO；v2.1 硬件批量 | 先正确后性能 |
| 像素格式 | ARGB8888 + RGB565 | **只做 RGB565** | 带宽减半，1080p 必需 |
