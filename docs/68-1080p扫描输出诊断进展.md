# 68 - 1080p 扫描输出问题：诊断与复现进展（进行中 · goal 第 1 轮）

> **这是 goal `goal-010c88c5`「256 精灵 1080p@60」的工作记录。** 接 [67](67-潜伏的307Hz：显示bug与性能bug.md)。
> **一句话**：已**复现** 1080p 扫描输出的分段读缺陷 —— 错误像素**全部从 h=1024 开始**，即第二段数据接错。

**对比**：640 宽（480p 参数）时应用**能跑完**（total=10），但输出 307 Hz。
**⇒ 1920 宽 = 挂死；640 宽 = 能跑但显示不对。** 那两行 `H_ACT(640)/V_ACT(480)` 覆盖很可能是当年为了"能用"而做的**治标**。

## 三、关键观测（下一步的起点）

```
AR 序列（地址与长度都正确）:
  t=294685000 id=1e addr=08000000 len=255   ← 段0: 256 拍 = 1024 像素
  t=297315000 id=1e addr=08001000 len=223   ← 段1: 224 拍, +4096 字节 ✅
  t=299635000 id=1e addr=08002000 len=255   ← 下一行段0, +8192 = stride ✅

像素错位:
  PIX MISMATCH v=0 h=1024 got=000000 exp=1024
  PIX MISMATCH v=0 h=1025 got=000001 exp=1025
```

**⇒ AR 完全正确，但第二段的数据"接错了"**：h≥1024 时输出的是 `exp − 1024`，即**看起来像"行首的数据被重复/偏移了一段"**。

**⇒ 待查的三个方向**：
1. `bitblt_video_out` 里**段的边界如何并入像素流**（`rd_px` / `px_in_line` 在段切换时是否重置）；
2. **FIFO 写入侧**（`rd_row` 与 FIFO 的关系，注释里提到过"wcnt=512 need_line=0"）；
3. `total_beats`/`seg_beats` 的**长度计算**（256+224=480 拍 = 1920 像素 ✅ 数对，但**拼接**可能错）。

## 六、第 4 轮（终局）：**根因确认 + A/B 证明** —— goal 判据 ① 达成

### 根因（一句话）

**扫描输出发一段 256 项的 burst 时，若 FIFO 装不下这一段，`rready = ~fifo_full` 会在 burst 中途落下
⇒ burst 永远完不成 ⇒ 读 FSM 卡在 `S_R` ⇒ 卡住 Axi_Mux 的 R 通道 ⇒ 顺序 DDR 不再服务任何 AR
⇒ 引擎的 `rd0/rd1` 一起饿死**（板上的 `AR handshake wedged` + `active lines = 0`）。

### A/B 对照（决定性证据）

| 版本 | `tb_mux_video`（1920 宽 + 64 个并发 S0 burst）|
|---|---|
| **无准入**（修复前行为）| ❌ **复现**：`T3 1..4: fifo_empty=1`（停滞）；`T3 5: state=2 fifo_full=1 wcnt=512` ⇒ 卡在 S_R |
| **有准入**（修复）| ✅ **PASS**：29001 像素零错 · S4 发满 32 个 AR · rows seen 15 |

**板上读数与之逐字对应**（`state=S_R` + `fifo_full=1`）。

### 修复

```verilog
localparam [16:0] FIFO_ENTRIES = 17'd1 << (FIFO_AW - 2);
wire [16:0] fifo_free = FIFO_ENTRIES - {1'b0, wcnt16};
wire        seg_fits  = (fifo_free >= {1'b0, seg_beats});
```

**两个条件同时成立才安全**：
1. **发起前**要求段能整体装下（`S_IDLE` 与 `S_AR` 的"未请求"分支）；
2. **一旦 ARVALID 拉高，必须持到 ARREADY** —— Axi_Mux 的 AR 仲裁器在 `S_ADDR_IDLE` 锁存请求通道，
   只在 `M_A_End` 释放，而 `M_A_Valid = |(Act_Cnl_List & S_A_Valid)` **只看锁定通道**：
   **握手前撤 arvalid ⇒ M_A_Valid 落 ⇒ M_A_End 永不触发 ⇒ 该通道永久占死** ⇒ 饿死所有 master。

### ⚠️ 差点亲手造出这个死锁

我的第一版准入写成 `else arvalid_r <= 1'b0`（即"装不下就撤请求"）—— **那正是"握手前撤 arvalid"**，
会触发上面那条锁存死锁。拦住它的是 tb 里一段我先前没读到的注释：
*"Dropping arvalid before the handshake makes M_A_Valid fall to 0, so M_A_End never fires and
S_A_Ready stays stuck on channel 0 forever -- starving every other master."*

**⇒ 教训**：**准入只能拦"发起"，绝不能中止"已发出的请求"**。
