## 四、⭐ 反向验证原则（本项目最有价值的一条）

**⇒ 出自 [22](22-审计问题修复记录.md)：**

> **每一项修复都必须配一个【反向验证】：临时退回旧实现，确认测试**确实会失败**。**
> **⇒ 若退回后测试仍通过，说明这个测试根本没在测那件事。**

**⇒ 这条原则的实战效果 —— [22](22-审计问题修复记录.md) 里 9 项修复的反向验证：**

| 问题 | 反向验证的结果 |
|---|---|
| **`sim.ps1` 只看退出码** | **构造 TB 报 `RESULT: FAILED` 而 `vsim` 报 `exit 0`** |
| **`audit-bitblt.ps1` 防不住资源塌方** | **注入 `u_bitblt` 缩水，基线对比触发** |
| **`reg_bpp` 只有 3 位** | **退回 `r_bpp[2:0]` ⇒ 测试 FAIL** |
| **`dma_wr` B 通道握手未闭合** | **变体 B ⇒ 旧版 `TIMEOUT state=2`** |
| **`alpha_blend` 用 `>>8` 代替 `/255`** | **退回 `>>8` ⇒ `199 vs 2xx` 差异** |
| **`tb_*` 无条件打印 PASS** | **注入期望值错误 ⇒ 断言真的失败** |

**⇒ 这条原则后来成了本项目的标准做法**：P3/P4 的每一次改动都配了故障注入（见 [42](42-P3突发合并实现记录.md) / [43](43-P4实现记录.md) / [44](44-P4弹幕能力记录.md)）。

## ⭐ 两个仿真器抓到的东西（2026-10-07）

**⇒ 起因**：用户要求「跑交叉仿真」—— 即 iverilog 与 Questa 各跑一遍。**⇒ 动机是「多跑一次仿真就能少一点问题」。**
**⇒ 结果**：一次就抓到四类问题，其中一类**改变了综合结果**。

### 一、`bitblt_top.v`：19 处「隐式 1 位 wire」—— 而它**真的影响电路**

| | |
|---|---|
| **现象** | **19 个信号在模块例化的端口连接里被使用，而 `wire` 声明在文件更靠后的位置** |
| **⇒ 工具分歧** | **iverilog 默认**静默通过**（只有 `-Wall` 报 `implicit definition of wire`）；Questа **直接报错**（`already declared in this scope`）；Efinity **无任何报告** |
| **⇒ 为什么严重** | **Verilog 把未声明标识符当**1 位 wire**。19 个里 **17 个是 16 或 32 位** —— `st_rt_sel[15:0]`、`mon_sticky[15:0]`、`addr_oob_addr[31:0]`、`rd_src_data[127:0]` 等** |
| **⇒ 实测后果** | **修复后综合 LUT4 从 **15444 → 15712（+268）**。只是把声明提前（语义等价），资源却变了 ⇒ **说明隐式 1 位时综合器只连了 1 位**，即**修复前综合出的电路是不完整的**** |
| **⇒ 结论** | **那不是代码风格问题，是**真实的电路差异**。若上板，`SPR_RT_SEL` 可能只能选 0/1 两个字而非 8 个** |

### 二、两处「字面转义串」坏代码

**⇒ 早前某个脚本把 `\r\n` 当**字面文本**写进了 `.v` 文件 ⇒ 整段语句被压成一行，中间夹着反引号 r 反引号 n。**
**⇒ iverilog 接受它（回归全过），Questa 报 `` Macro `r is undefined ``。**

| 位置 | 内容 |
|---|---|
| **`tb_bitblt_top.v`** | **前 8 个 AR 地址的打印循环被压成一行（交叉仿真当场发现）** |
| **`tb_bitblt_sprite_walker.v:384`** | **`blit_count = 0;` 与 `fetch_count = 0;` 被压成一行** |

### 三、回归因此加了两道**硬失败**判据

| 判据 | 做法 |
|---|---|
| **隐式声明** | **编译加 `-Wall`；出现 `implicit definition` ⇒ **该测试直接判失败**** |
| **⇒ 字面转义串** | **源码扫描，精确匹配反引号 r 反引号 n（**不用宽松匹配** —— Verilog 合法地用反引号做宏，如 `system_top.v` 的 `` `RANKS ``，宽松匹配会误报并被关掉）** |

**⇒ 两道判据都做了**注入测试**证明能失败：**
- **删掉 `wire fifo_re;` ⇒ 3 个 tb 报 FATAL ⇒ `REGRESSION: 3 FAILED`** ✓
- **写一处字面串 ⇒ `REGRESSION: 1 FAILED`** ✓

### 四、还有两类**已发现但暂未设为失败**的警告

**⇒ 它们是真的，但各自有独立的工作量；一次性打开会让回归因**与本次无关的原因**变红，而一个**因为已知原因长期红着**的回归就不再被读。**
**⇒ 所以现在**打印计数并在总结里列出**，不是静默放过：**

| 类别 | 数量 | 含义 |
|---|---|---|
| **`dangling input port ... floating`** | **18** | **某些 tb 没连某些输入端口 ⇒ **那段路径在该 tb 里没被测**** |
| **`Unsized expression ... clipped to 65568 bits`** | **6** | **移位用了未指定位宽的常数 ⇒ 结果依赖巧合而非保证** |

**⇒ 两者都已列入待办；把它们设为失败之前，要先处理它们本身。**

### 五、方法论结论

**⇒ 单仿真器会放过真实的缺陷。** **⇒ 本项目此前的 24 项回归 + 全链路 7 阶段**全部通过**，而它们**都没看见**那 19 处隐式声明。**
**⇒ 代价对比：跑一次 Questa 约 6 秒（单测试），而板上一旦表现出「`SPR_RT_SEL` 只有两个值可用」这类症状，定位成本远高于此。**

### 六、第二轮：Questa 又抓到一处，以及判据的一个盲区

**⇒ 三个测试台在 Questa 上跑通之后，`tb_bitblt_sprite_walker` 又报出 10 个错误：**

```
(243) Undefined variable: 'cap_w'
(257) 'Formal' must not be declared to be an array: cap_src
```

**⇒ 根因和 `bitblt_top.v` 的 19 处**完全一样** —— 五个数组 `cap_src/dst/w/h/ss` 的 `reg [...] [0:15]` 声明写在了**写它们的 `always` 块之后**（声明在行 257–261，首次使用在行 241）。**
**⇒ Questa 那句「Formal must not be declared to be an array」是它隐式创建形式参数时的措辞，不是真的把数组当形参。**
**⇒ 修法与之前一致：把声明移到那个 `always` 块之前（模块级）。修后 iverilog 0 错误、Questa `RESULT: PASS (walked 4 sprites)`。**

**⚠️ 第一次修错了位置** —— 我把声明插到 `// addr_gen stub` 那行之前，而**那行注释在 `always` 块内部**，于是 `reg` 声明出现在块里，产生 `syntax error: malformed statement`。**教训：Verilog 的声明必须插在模块级，不能插在块内；找一个 `always` 之前的位置，而不是一条看起来合适的注释之前。**

### 七、判据的**盲区**（重要，且只有跑 Questa 才暴露）

**⇒ `tb_bitblt_sprite_walker` 那 5 个数组的「先使用后声明」，**iverilog `-Wall` 一句都没报**。**
**⇒ 所以回归新加的 `implicit definition` 判据**抓不到这一类** —— 它只覆盖标量信号。**

| 工具 | 对那 5 个数组的反应 |
|---|---|
| **iverilog -Wall** | **静默** |
| **Questa** | **10 个错误，拒绝文件** |

**⇒ 结论**：**回归的判据不可能覆盖全部**，而**周期性跑 Questa 是补这个盲区的唯一办法**。
**⇒ 所以 [docs/48](48-片上断言监控.md) 与本文都记了这一条：**「iverilog 干净」不等于「代码正确」。****

### 九、那 18 条悬空输入端口：判定与处理（2026-10-08）

**⇒ 回归的 tracked 清单当时报出 18 条 `dangling input port`。逐个判定后，它们**不是同一类东西**。**

| # | 测试台 | 悬空端口 | 判定 | 处理 |
|---|---|---|---|---|
| **①** | **`tb_bitblt_axi_slave`（8）** | **`spr_rt_bits` `scan_blanking` `scan_short_count` `addr_oob_addr` `mon_sticky` `mon_cnt` `spr_pos_xy` `spr_pos_valid`** | **⚠️ **真实覆盖缺口**** | **✅ 应驱动** |
| **②** | **`tb_bitblt_regs`（4）** | **`scan_short_count` `addr_oob_addr` `mon_sticky` `mon_cnt`** | **⚠️ 真实覆盖缺口** | **✅ 应驱动** |
| **③** | **`tb_bitblt_top`（4）** | **`st_rd_live` `scan_blanking` `scan_short` `scan_short_count`** | **⚠️ 真实覆盖缺口**（而该 tb **已经**连了 `mon_sticky` 等 ⇒ 只有这 4 个漏了）** | **✅ 应驱动** |
| **⇒ ④** | **`tb_bitblt_sprite_walker`（2）** | **`dbg_req` `dbg_idx`** | **⇒ **有意不连****（该 tb 测遍历器；位置读回另有 `tb_bitblt_posread`）** | **✅ **已显式接 0 + 注释**（2026-10-08 完成）** |

**⇒ 为什么 ①②③ 是「真实缺口」而不是「接 0 就行」：**

**⇒ 那些**都是寄存器文件【回读【路径【的【输入** —— `0x4C SPR_RT_BITS` 读的是 `spr_rt_bits`，`0x60/0x68` 读的是 `mon_sticky`/`mon_cnt`。**
**⇒ **⇒ 而【那两个【tb 测的【正是【寄存器【读写 ⇒ **把【它们【接 0 等于【宣称「【读回【永远是 0」是【可接受的」—— 而那【不是【测试，是【掩盖**** ✗
**⇒ ⇒ ⇒ 【要【驱动【它们，并【断言「写【了【选择【寄存器【之后【读到的【就是【喂【进来的【值」—— 【那【才【是【读回【路径【的【测试。****

**⇒ 而【那【是【一定【的【工作量：每个【tb 要【加【驱动【信号 + 例化【连接 + 断言。**
**⇒ 在【它【完成【之前【它们【留在 `tracked`（**打印【计数**，不【判【失败）—— **理由【同§八：长期【红着【的【回归【不再【被【读**。**
