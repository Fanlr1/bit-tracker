# 122 · GFX 引擎完整架构与优化上限分析（2026-11-01）

> 结论：**引擎已到资源约束下的架构极限，无法再优化**
> 唯一出路：**降低输出分辨率（720p）**

## 一、架构总览

```
gfx_top
├── gfx_regs    (AXI4-Lite 寄存器 + 8 深命令 FIFO)
├── gfx_core    (15 状态 FSM，命令执行核心)
├── gfx_mem     (DDR 仲裁: rd0/rd1=scanout, rd2=引擎读, wr=写)
└── gfx_scanout (1080p 时序发生器 + 行缓冲)
```

## 二、资源占用（XLR）

| 模块 | XLR | 占比 | 备注 |
|---|---|---|---|
| **u_gfx** | **35005** | **57.6%** | 引擎主体 |
| u_sapphire_soc | 8902 | 14.6% | IP，不可改 |
| u_ddr3_top | 5282 | 8.7% | IP，不可改 |
| u_dvi_encoder | 400 | 0.7% | 很小 |

引擎内部：`xlr_lut4` 22408、`xlr_ff` 9895、`mem` 134。

## 三、性能瓶颈（实测）

| 指标 | 数值 |
|---|---|
| 每命令耗时 | **7.2 µs** |
| 其中等 DDR 读 | **~6.5 µs（90%）** |
| `rdw` 读等待周期 | 647 cycles |
| 700 精灵 | 引擎 ~10 ms |
| 900 精灵 | 引擎 ~13 ms（超 16.7 ms 预算边缘）|

**瓶颈 = 每个精灵要从 DDR 读源数据**：
- 16×16 精灵 = 512 字节
- **`spx[0:127]` 只有 128 像素（256 字节）** → 16×16 精灵需要 **2 段** → **2 次 DDR 读**
- 900 精灵 = 1800 次 DDR 读/帧

## 四、为什么优化不了（逐项排除）

| 优化方案 | 结果 | 原因 |
|---|---|---|
| **spx 扩到 256 项** | ❌ 已试（`gfx_core.v.try256`）| PnR 资源爆：BRAM 只有 1-2 读端口，而像素合成需要 **8 个并行读端口** → 只能综合成 LUTRAM → 资源爆炸 |
| spx 改 BRAM（ramstyle=block）| ❌ 已试（try256 里就是）| 同上，8 并行读与 BRAM 端口数冲突 |
| 缩小 spx 到 64 项 | ❌ 反向 | 段数变 4 → DDR 读次数翻倍 → 更慢 |
| 预取/双缓冲 | ❌ 等价于 256 项 | 需要 2×128 项存储 |
| 精灵源缓存（同地址跳过读）| ❌ 等价于 256 项 | 需要整精灵缓存 |
| 省 LUT（乘法器改累加等）| ❌ 收益不足 | 3-5% LUT 改变不了 PnR 布局抽签性质 |
| 精简 SoC 外设 | ❌ 收益不足 | SoC 只占 14.6%，砍完省 5% |
| 加深命令 FIFO（8→32）| ⚠️ 无害但无益 | CPU 不是主瓶颈（引擎才是）|

## 五、核心矛盾

```
spx 需要 8 个并行读端口（一行 8 像素同周期取）
       ↕ 硬件约束
BRAM 只有 1-2 个读端口
       ↓ 所以
spx 必须是 LUTRAM → 128 项就是 LUTRAM 预算上限
       ↓ 所以
16×16 精灵必须分 2 段读 → 引擎吞吐受限于 DDR 读延迟
       ↓ 所以
900 精灵 = 13 ms 引擎时间，贴着 16.7 ms 预算
```

## 六、唯一出路：720p

| | 1080p | 720p |
|---|---|---|
| 像素时钟 | 148.5 MHz | 74.25 MHz |
| TMDS 串行 | 742.5 MHz | **371 MHz** |
| scanout DDR 读 | 4.15 MB/帧 | **2.07 MB/帧** |
| 每帧行数 | 1080 | 720 |
| 引擎命令预算 | 16.7 ms | 16.7 ms（同样）|
| **精灵容量** | ~700-900 | **~1000-1400**（scanout 让出带宽）|
| **DVI 稳定性** | 742 MHz 临界 | **371 MHz 宽松** |

**改动清单（6 处）**：`peri.xml` PLL 分频、`system_top_gfx.v` 时序、`gfx_scanout.v` 参数、`main.c`/`game.h` 分辨率宏、`bg_art.h` 背景尺寸。
