## 三、未完成的部分

**B 与 C 尚未单独验证**（它们是不是真凶，还差两步）。但它们都是**慢态修复尝试**，
按 [docs/92](92-慢态尝试与未确证.md) 的结论本就**未确证有效**——所以：

- **为了交付**：不需要它们，step 2 已经够用；
- **为了研究慢态**：将来需要时，按同样方法单独加回、单独验 `copy-readback`，就能知道它们是否就是那 959,128 的来源。

## 四、这一步为什么值得

**分离了"想要的功能"和"有害的改动"。** 之前 10-24 全量和 01:00 版二选一：
要么没漂移修复但数据对（01:00），要么有漂移修复但数据坏（10-24）。
bisect 之后拿到了**两者兼得**的版本。

## 五、教训

**"一次只加一处"不是洁癖，是效率。** 上一轮用 171 秒构建 + 90 秒上板去排除 `o_blanking`（白费），
这一轮同样的成本却直接定位到"三处之内"。分组 bisect（先全摘、再分组加回）比逐个排除快一个数量级。
